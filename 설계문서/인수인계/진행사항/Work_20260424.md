## 2. 오늘의 작업 내용

### 2-1. 시스템 아키텍처 수립 및 시퀀스 구조 배치
- [x] **테스크 분리:** Main Loop(중량 작업, 흐름 제어)와 TIM4(10ms 주기 UI/애니메이션)로 역할 분담.
- [x] **시퀀스 정의:** Main SQ 9단계 및 LCD SQ 9단계를 각각 `DM_Main_Sq_App.c`와 `DM_LCD_Stick_Check_App.c`에 배치.
- [x] **메인 루틴 연결:** `User_Main.c`를 통해 각 시퀀스 처리 함수를 메인 루프 및 인터럽트 서비스 루틴에 통합.

### 2-2. 저전력 관리 및 웨이크업 가드레일 구현
- [x] **IDLE 단계 구현:** MCU Halt 모드 진입 전 주변장치 저전력 설정(`Power_PrepareSleep`) 적용.
- [x] **안정적 복구:** Halt 해제 후 즉시 다음 단계로 넘어가지 않고, 200ms 동안 `SystemSleep_10ms()`를 호출하며 스틱 삽입 상태를 최종 검증하는 로직 추가.
- [x] **전력 최적화:** TIM4를 상시 가동하지 않고 `SystemSleep_10ms()` 호출 시에만 활성화하여 대기 전류 최소화.

### 2-3. EEPROM 애플리케이션(`DM_Rom_Handl_App`) 구축
- [x] **데이터 관리 레이아웃 확정:**
    - 0번지: Insert Count (1 Byte)
    - 1번지: Test Complete Count (1 Byte)
    - 2번지: Error Step (1 Byte)
    - 3번지: Error Code (1 Byte)
    - 4~19번지: Stick PTR Data (8 Shorts / 16 Bytes)
    - 20~243번지: Result History (7 Channels * 32 Bytes = 224 Bytes)
- [x] **가드레일 적용:** 모든 Read 함수에 대해 초기 상태(`0xFF`/`0xFFFF`) 감지 시 `0`으로 자동 초기화하는 로직 포함.
- [x] **순환 저장 구현:** `Test Complete Count`를 기반으로 7개 채널을 Overwrite 하는 결과 저장 로직(`DM_App_Rom_Save_CurrentResult`) 구현.
- [x] **표준화:** 모든 함수에 Doxygen 주석 추가 및 명칭 통일(Cassette -> Stick).

### 2-4. 하드웨어 드라이버 보완
- [x] **LED 채널 제어:** LED1, LED2를 개별 제어하는 `DM_HW_Drv_LED_Control` 추가.
- [x] **상호 배제(Mutual Exclusion):** 두 LED가 동시에 켜지는 것을 방지하기 위해, 한 채널을 켤 때 다른 채널을 명시적으로 끄는 안전 로직 적용.

### 2-5. 광학 계측 애플리케이션(`DM_Optic_Handle_App`) 보완
- [x] **초기 데이터 측정 및 백업:** 스틱 삽입 시 4개 채널에 대해 PWM 199, 399 조건에서 PTR ADC 값을 측정하고 EEPROM에 백업하는 `DM_App_Optic_MeasureInitialStick` 구현.
- [x] **정밀 타겟 튜닝 로직:**
    - 전달받은 대상 ADC 값에 도달할 때까지 PWM을 반복 계산하여 조정하는 `DM_App_Optic_TuneTargetADC` 함수 작성.
    - **피드백 제어:** 측정된 ADC 오차와 초기 기울기 정보를 결합하여 다음 PWM 값을 동적으로 재계산하는 P-Control 방식 적용.
- [x] **공시료 및 결과 계측 구현:**
    - 튜닝된 PWM을 사용하여 공시료 상태의 ADC를 측정하는 `DM_App_Optic_MeasureEmptyPTR` 추가.
    - 반응 완료 후 최종 결과 ADC를 측정하는 `DM_App_Optic_MeasureResultPTR` 추가.
- [x] **데이터 인터페이스(Getter) 강화:**
    - 튜닝된 PWM 값, 공시료 데이터, 결과 데이터 배열을 외부에서 참조할 수 있는 인터페이스 함수(`GetPWM`, `Get_EmptyPtrData`, `Get_ResultPtrData`) 구현.
- [x] **가드레일 및 반응성:** 
    - 모든 계측 루프 중 약 100ms 간격으로 스틱 이탈 여부를 체크하여 즉각적인 중단이 가능하도록 설계.
    - 채널당 최대 5회 반복 제한을 통해 안정성 확보.

### 2-6. 성능 분석 (시간 예측)
- **`DM_App_Optic_TuneTargetADC()` 소요 시간:**
    - **최대(Worst Case):** 약 **2.0초** (4채널 × 5회 반복 × 100ms 측정시간).
    - **최소(Best Case):** 약 **0.4초** (4채널 × 1회 측정 즉시 완료).
