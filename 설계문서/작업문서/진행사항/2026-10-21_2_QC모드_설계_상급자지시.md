# QC 모드 — 최초 5회 기록과 사용자 구간 무음 처리

- 날짜: 2026-10-21 (지시 수령)
- 브랜치: `feature/stage10-wake-fail-record`
- 단계: **11단계** (착수 전). 기존 11단계였던 「살짝 빠짐」은 **12단계**로 미룸
- 상태: 🔵 설계만. 구현 안 함

> **한 줄** — 증가 후 Insert Count 1~5는 **QC 구간**으로 보고 네 채널 원본값 한 벌을 별도 공간에 남긴다.
> 6 이상은 **사용자 구간**이고, 초기 광학 판정 실패 시 **화면에 아무것도 띄우지 않고 다시 잔다.**

> **경위** — 내가 먼저 안을 설명하고 "어떠세요" 라고 여쭌 데 대한 답으로 나왔다.
> 상급자는 **판정 방법은 지금 있는 관문 두 개로 충분하다**고 보셨고,
> 대신 **구간(QC / 사용자)에 따라 화면 처리를 다르게 하고 QC 값을 남기라**고 하셨다.
>
> | | 내가 제안한 것 | 상급자 답 |
> |---|---|---|
> | Insert Count 로 최초 판별 | 하자 | **받아들임** |
> | 판정 방법 | 채널 간 최대−최소 편차 | **기존 관문 두 개로 충분** |
> | 목적 | 기기가 불량을 걸러냄 | **QC 수행 증거 + 사용자에게 안 보이기** |

### ① QC 수행 증거를 남긴다 — 이게 진짜 목적이었다

> [05:08] "0부터 5 사이면 이게 이제 **QC 모드** 쪽이라고 생각하고 ...
> 그게 최초 값들을 저장을 해서, **고객한테 값이 낮은 게 나갔다는 얘기는 QC 안 했다는 얘기거든.
> 그거는 우리 문제가 아닌 거지. 저쪽에서 QC 안 한 문제인 거지.**"

> [12:08] "**나갔는데 원인을 몰라서 서로 불똥이 튀는 거 되게 많아.**
> 예를 들면 얘네가 검선을 했는지 안 했는지.
> — 덤프 뽑으면 그게 증거가 나오겠네요?
> — **그렇지. 증거가 딱 나오는 거지.**"

**불량 검출이 아니라 책임 소재를 가리는 증거**다.
QC 구간의 네 채널 원본값을 사후 확인 자료로 남긴다. 낮은 값만으로 QC 미수행을 단정하지 않는다. QC 중 불량값이 측정된 기록일 수도 있다.

### ② 사용자에게는 에러를 보이지 않는다

> **전제 — 판정은 LCD 가 켜지기 전에 끝나야 한다.**
>
> > [01:52] "**디스[플레]이가 동작되기 전에 [판단]을 내려야 될 것 같은데**"
>
> LCD 가 한 번 켜지면 사용자는 "기기가 깨어났다" 고 본다. 그 뒤의 에러는 **고장**으로 보인다.
> 켜지기 전에 끝내면 **애초에 안 깨어난 기기**로 보인다. 이 차이가 아래 모든 것의 근거다.

> [12:36] "얘가 문제가 생겼을 때 **시중에 나가서는 에러가 뜨면 안 돼.
> 아예 동작을 안 하는 게 나아.**"

> [14:00] "— **유저가 볼 때 문제가 없는 것처럼 보이게 하는 게 관건인 건가요?**
> — **그렇지. 그것도 핵심인 거지.**"

> [14:00] "눈으로 보기에는 LCD가 안 켜져 있으니까 웨이크업 상태가 아닌 거지.

그러면 사용자는 스스로 다시 꽂는다.

> [15:52] "유저가 자기가 잘못 꽂아서 이렇게 빠졌나 그러면 다시 꽂겠지.
> 빼다가 다시 꽂겠지. 그래가지고 저 상황을 벗어났으면 이제 제대로 동작을 할지"

## 두 구간

| | 증가 후 Insert 1~5 | 증가 후 Insert 6 이상 |
|---|---|---|
| 이름 | **QC 구간** | **사용자 구간** |
| 네 채널 원본값 | **별도 공간에 저장** | 저장 안 함 |
| 이상할 때 | **에러 화면 띄움** | **아무것도 안 띄우고 IDLE 로** |
| 에러 후 대기 | **2분 그대로** (`ERROR_WAIT`) | **없음. 즉시 IDLE** |
| 코드 변경 | **측정·저장 순서 변경. 에러 표시와 2분 대기는 유지** | **판정 후 LCD 시작, 실패 시 무음 복귀** |
| 누가 보나 | QC 담당자 (그 자리에서) | 회수 후 덤프로 |

> **QC 구간의 2분 대기는 그대로 둔다 (2차 녹음 10-22 확인).**
>
> > [00:28] "QC 모[드]가 ... **양[산] 테스트 모[드]**라고 할 수 있는 [무대]일 것 같아.
> > 그때는 [에러를] 띄워줘야지. **시간 대기를 [넣은] 기간 그대로 [유지].**"
>
> "2분이 길어 QC 작업이 느려지지 않나" 를 여쭸으나, 양산 테스트 자리이므로
> 검선자가 에러를 충분히 보는 쪽이 맞다는 답이다.
> → **에러 표시·대기 정책을 바꾸는 곳은 사용자 구간이다.** QC 측정·저장 순서는 아래 합의에 따라 바꾼다.

### 왜 5회인가

> [06:32] "5개, 3개를 할지는 일단 **5개를 기준으로 잡자.
> 왜냐하면 테스트하다 보면 리젝되는 경우가 있으니까.**"

QC 과정에서 몇 번 실패할 수 있으므로 여유를 둔다.

> **숫자 주의** — 녹음에서 "0부터 5"와 "0부터 4"가 오간다. [11:12] 에서 정리된다.
>
> > "0부터 5까지는 아니라 **0부터 4까지는 저장을 시켜야지.**
> >  0부터 4까지는 저장을 시켜야 되는데 **5부터는** 저장을 안 시켜야 되는 거잖아요.
> >  **0부터 5까지는 QC 모드로 보는 거지.**"
>
> 최초 **5회**를 뜻한다. 녹음의 0~4는 0부터 센 회차이며, 구현에서는 **증가 후 카운터 1~5**로 통일한다. 인용 원문은 그대로 둔다.

### 제안했다가 단순화된 부분 (내 안)

> 기준서 규칙(계획은 결과와 달라도 지우지 않는다)에 따라 남긴다.

내가 제안한 것은 **채널 간 최대−최소 편차**였다.

```
최초      →  네 채널 중 최대와 최소를 비교. 편차가 크면 에러
최초 아님  →  처음 꽂았을 때 값 대비 비교
```

근거로 삼은 실측 (2026-10-20·21)

| 기기 | CH0 | CH1 | CH2 | CH3 | 최대−최소 |
|---|---|---|---|---|---|
| 1 (정상) | 3,723 | 3,702 | 3,703 | 3,695 | **28** |
| 5 (정상, 10-20) | 3,712 | 3,716 | 3,716 | 3,691 | **25** |
| 11 (정상) | 3,745 | 3,737 | 3,747 | 3,687 | **60** |
| **5 (저하, 10-21)** | 3,255 | 3,175 | 3,073 | **2,765** | **490** |

정상은 60 이내(1.6%), 저하된 5번은 490. **네 값 모두 1,500~3,900 안이라 관문 1 은 통과시킨다.**

**이 구멍은 이번 작업으로 메워지지 않는다.** 상급자 지시는 판정을 더 넣는 것이 아니라
**QC 구간에 값을 남겨 사후에 가릴 수 있게 하는 것**이기 때문이다.

> 다만 폐기는 아니다. QC 구간(증가 후 1~5)의 네 채널 원본값을 덤프로 수집하면 그것이 **기준을 세울 데이터**가 된다. 기기에는 이력 다섯 벌이 아니라 한 벌만 남는다.
> 지금은 기준을 세울 만큼 데이터가 없다 — 정상 3대에서 25~60 이지만
> 광량이 35% 낮은 2번 기기는 보지도 않았고, 4단계의 채널 간 5% 기울어짐 원인도 모른다
> (기준서 7장 보류 항목 ⓐ). 문턱값 625 를 1대로 정했다가 틀린 전례가 있다.

## EEPROM 공간

> [04:12] "지금 4개잖아. 그러면 **8바이트**가 필요한 거지.
> 8바이트인데 8바이트가 **2개**가 필요하니까. 기존에 8바이트가 있고 8바이트가 더 추가로 필요한 거지.
> 이렇게 모자라면 **총 7개 저장할 수 있게 되어 있는 거 하나 줄이고 6개에서 돌리는** 식으로"

> [11:40] "**원본값이 두 군데 저장이 되는 건데** ...
> 생산에서 검선을 했는지 아닌지 **확인용으로 메모리 블록 하나 더 있는 거야. 별도로.**"

| 용도 | 자리 | 크기 | 갱신 |
|---|---|---|---|
| 최근 초기값 (기존) | 4 ~ 19 | 8바이트 ×2 | 매 회차 덮어씀 |
| **QC 기준값 (신설)** | **212~219** | **8바이트** (4채널 × 2B) | **증가 후 1~5에서 완전한 한 벌로 덮어씀** |

### 공장 출하 상태와 QC 완료 상태를 구분해야 한다

> [14:56] "[덤프] 딱 찍어[봤]는데 **[기록]도 없고**, 출[하 때] 값이 이렇게 낮았다 —
> 이거는 [검]선을 안 한 기계다 라는 [판단]을 할 수 있는 거잖아."

**QC 구간 공간이 비어 있으면 "완전한 QC 측정 기록이 남아 있지 않다" 는 뜻이다.** 초기화로 지웠거나 CH3 관문에서 중단했을 수도 있으므로 QC 미수행으로 단정하지 않는다.

그러려면 **아직 안 쓴 상태**와 **쓴 상태**가 구별되어야 한다.
EEPROM 공장 출하 상태는 `0xFFFF` 이므로 그대로 두면 구별된다 — 10단계 ③ 에서
`Get_WakeFail()` 이 쓴 방식과 같고, 그 원형은 `Get_StickPtrData()` (`DM_Rom_Handl_App.c` 159행) 다.

> 다만 10단계 ③ 과 달리 여기서는 **0 으로 정리해 버리면 안 된다.**
> 정리하는 순간 "안 썼다" 와 "0 이 찍혔다" 가 섞인다.
> QC 구간 공간은 **FF 를 그대로 둬야** 한다.

### 새 EEPROM 지도 — 레코드 7칸 → 6칸 (2026-10-22 확정)

> [04:12] "모자[라]면 **총 7개 저장할 수 있게 되어 있는 거 하나 [줄]이고 6개에서 [돌리]는** 식으로"

```
  0 ~   3   상태값 (Insert / TestComplete / ErrorStep / ErrorCode)
  4 ~  19   StickPtrData 16바이트 (매 회차 덮어씀)
 20 ~ 211   결과 레코드 6칸 x 32 = 192바이트      <- 224 에서 줄어듦
212 ~ 219   QC 기준값 8바이트 (4채널 x 2B)        <- 신설
220 ~ 243   비어 있음 (24바이트)
244         덤프 위치
245 ~ 247   비어 있음 (244 와 같은 4바이트 블록)
248 ~ 251   헛깨어남 범위 (10단계 ③)
252 ~ 255   비어 있음 — 초기화 완료 표식 자리로 남겨둔다 (지금은 쓰지 않음)
```

## 코드 변경 지점

### ① Insert Count 를 0단계(IDLE)에서 올린다

> [04:40] "**인서트 카운터를 IDLE 쪽에서 증가시키는 거지.**
> — 인서트를 IDLE 에서 넘어갈 때?
> — 맞아요. **IDLE 에서 증가시켜요.**"

현재는 1단계(`Stick_Insert_Step_Handler`)에서 읽고 +1 한다. 아래 코드는 변경 전 동작이다.

```c
gs_bStickInsertCnt = DM_App_Rom_Get_InsertCount();
gs_bStickInsertCnt++;
DM_App_Rom_Set_InsertCount(gs_bStickInsertCnt);
```

> [02:48] "**지금은 인서트 카운트 체크하는 게 없어.**
> 근데 인서트 체크하는 걸 집어넣게 되면 **최초인지 아닌지를 판별할 수 있잖아요.**"
>
> 읽기는 하지만 **분기에 쓰지 않는다**는 뜻으로 읽었다.

#### 확정한 증가 위치와 회차 정의 (10-22)

IDLE 핸들러에서 **초기 CH3 관문을 통과할 때마다 1씩 증가시키되, 254에서는 유지**한다.
증가 후 **1~5는 QC, 6 이상은 사용자 구간**으로 확정하고 그 회차 동안 유지한다.
초기 CH3 실패는 세지 않는다. 증가 이후에는 측정 시작 전 중단을 포함해 어디서 실패하든 해당 회차에 포함한다.
기존 1단계의 증가 코드는 제거하여 한 회차에 두 번 증가하지 않게 한다.

**254에서 멈추는 이유:** 255(`0xFF`)를 저장한 뒤 `Get_InsertCount()`로 다시 읽으면 미기록 상태로 해석되어 0으로 초기화된다.
이로 인한 QC 재진입을 막는다. 254는 사용 횟수 제한이 아니며 기존 Test Complete Count 사용 제한 정책은 별개로 유지한다.

상급자가 직접 지정한 것은 **IDLE에서 증가**까지다. **관문 통과 후 증가·실패 회차 계산·254 포화**는 이번 논의에서 확정한 구현 정책이다.

#### 결과 레코드는 카운터와 독립적으로 순환한다

Insert Count가 254에서 멈춰도 결과는 여섯 칸을 계속 순환해야 한다.
현재 정상·에러 저장 경로의 `Insert Count - 1` 기반 슬롯 계산을 덤프 위치 기반 순환으로 교체하고, 같은 회차를 중복 저장하지 않게 한다.
초기화 후 첫 결과의 슬롯과 덤프 위치 갱신 순서를 일관되게 정하며, 덤프 위치는 **마지막 저장 슬롯**이라는 의미를 유지한다.
관문 실패 등 결과 레코드를 쓰지 않는 경로에서는 위치를 이동시키지 않는다. 최신순 덤프도 같은 위치를 기준으로 읽는다.

### ② 측정과 판정을 분리하고, 판정 후 LCD 를 켠다 (10-22 합의)

```
깨어남 → 현재 Insert Count 읽기 (초기 CH3 실패 시 화면 처리는 현재 count < 5이면 QC)
    ↓
CH3 존재 관문 (원본 2,600 이상) — 실패하면 중단, WakeFail 기록 유지
    ↓
통과하면 Insert Count 1 증가 (254에서 유지) → 증가 후 1~5 QC / 6 이상 사용자 확정
    ↓
각 채널 직전 CH3 확인 → 해당 채널 원본값 측정 (4채널 반복)
    ↓
마지막 CH3 확인 → QC 구간이면 완전한 네 채널 한 벌 저장
    ↓
관문 1: 네 채널 원본값 1,500~3,900 검사
    ↓ 통과할 때만
배율 계산 → 관문 2: 배율 적용값 1,175~1,225 검사
    ↓ 두 관문 모두 통과할 때만
정상 LCD 삽입 시퀀스 → 검사 진행

실패: QC 구간은 실패 기록 → 에러 LCD → 기존 ERROR_WAIT 2분
      사용자 구간은 실패 기록 → LCD 없이 IDLE
```

> **새 판정 기준은 넣지 않는다.** CH3 존재 관문과 기존 범위 관문 두 개를 유지한다.
> 측정·저장·판정 순서와 구간별 화면 처리를 바꾼다. 초기 CH3 실패의 기록은 기존 WakeFail 을 유지한다.

#### 범위 밖은 수집 계속, CH3 존재 관문 실패는 즉시 중단

- 한 채널이 1,500~3,900 밖이어도 나머지 원본값을 수집한다. QC 구간에서는 네 채널을 저장한 뒤 범위를 판정한다.
- **측정을 끝까지 한다는 것은 검사를 계속한다는 뜻이 아니다.** 범위 실패 시 배율 계산과 본 검사는 진행하지 않는다.
- 채널별 CH3 확인과 저장 전 마지막 확인은 유지한다. 실패하면 즉시 중단하고 **QC 기준값 한 벌은 갱신하지 않는다.** 미측정 채널을 0이나 이전 값으로 채워 저장하지 않는다.
- ADC timeout 은 기존의 제한된 대기와 반환 처리를 유지한다. 반환값 0은 실제 광학값 0과 구별되지 않는다.

**CH3 관문 실패가 실제 스틱 제거를 확정하는 것은 아니다.** 이 함수도 CH3 원본값을 2,600과 비교하므로 스틱 제거·광량 저하·광학계 고장·ADC timeout 을 구별하지 못한다.
중단 이유는 **측정 조건을 보장하지 못하기 때문**이다. 캐시 대신 새 측정값을 쓴다는 주석도 실제 제거를 확정한다는 뜻은 아니다.

따라서 **7·9번처럼 CH3부터 낮은 기기는 네 채널 QC 기록을 얻지 못할 수 있다.** 이것은 이번 설계에서 감수하는 한계다.
모든 불량 기기의 네 채널을 확보하려면 별도의 진단 측정 정책이 필요하며, 이번 합의에는 포함하지 않는다.
QC 기준값이 비어 있거나 이전 회차 값이 남아 있다는 사실만으로 이번 QC 수행 여부를 단정하지 않는다.

#### 정상 LCD 는 두 관문 통과 뒤에 시작한다

현재는 초기 CH3 통과 직후 LCD 삽입 시퀀스를 시작한다. 이를 **네 채널 원본값 검사와 배율 적용값 검사 모두 통과한 뒤**로 옮긴다.
QC 실패 시의 에러 LCD 는 예외다. 사용자 실패 시에는 삽입 애니메이션도 먼저 켜지 않아야 한다.
네 채널이 1,500~3,900 안이라는 이유로 CH3 2,600 관문 실패를 정상 처리하지 않는다.

#### LCD 반응 시간은 실측한다 — 250ms 로 확정하지 않는다

채널별 확인을 유지한 정상 경로의 측정 횟수는 다음과 같다.

| 측정 | 횟수 |
|---|---|
| 깨운 직후 CH3 관문 | 1 |
| 각 채널 직전 CH3 확인 | 4 |
| 실제 네 채널 측정 | 4 |
| 저장 전 마지막 CH3 확인 | 1 |
| **합계** | **10** |

측정당 50ms 라고 가정해도 약 500ms 다. **50ms 자체도 확정값이 아니다.**
코드의 명시적 대기는 LED 안정화 20ms 와 회복 10ms 이고 ADC·정렬·호출 비용 등이 추가된다.
QC 저장 비용까지 포함해 **SW1 감지부터 실제 LCD 첫 출력까지** QC·사용자 정상 경로를 각각 실측하고, 재삽입 반응도 확인한다.

#### 카운터 정책은 ①절로 통합해 확정

증가 후 기준으로 통일한다. `<= 4`를 증가 후 판정에 사용하지 않는다.
초기 CH3 실패는 카운터를 변경하지 않으므로, 그 실패의 화면 처리는 증가 전 현재 값이 0~4이면 QC, 5 이상이면 사용자로 구분한다.

### ③ 사용자 구간은 ERROR_WAIT 를 거치지 않고 IDLE 로 직행한다

**적용 범위는 초기 광학 판정 실패에 한정한다.** 초기 CH3 확인, 초기 측정 중 CH3 확인, 원본값·배율 적용값 관문 실패가 대상이다.
검사 진행 중 스틱 제거·시료 관련 오류·사용 횟수 초과 등 다른 오류의 표시와 대기 정책까지 일괄 무음 처리하지 않는다.

> [14:00] "그래서 **다시 [IDLE] 상[태]로 돌아가게 만드는 거지. 거기서 바로.**"
>
> [17:16] "**바로 에[러] 표시 [띄]우지 말고 바로 [IDLE]로 돌아가게** 해서"
>
> [17:44] "그니까 다시 이제 그 **아무것도 안 하고 다시 [IDLE] 상[태로] 돌아가는 거지.**"

세 번 모두 **"바로"**, **"아무것도 안 하고"** 다.

#### 화면만 끄면 안 된다 — 2분이 문제다

현재 에러 경로는 `DM_App_Main_Sq_Enter_Error()` → `MAIN_SQ_ERROR_WAIT` 다.
그 핸들러는 **2분을 기다린 뒤에야** IDLE 로 간다.

```c
/* DM_Main_Sq_App.c, Error_Wait_Step_Handler() */

/* 2. Run Wait Timer (2 minutes Animation/Delay) */
if (gs_wMain_Sq_Timer > 0)
{
    DM_HW_Drv_SystemSleep_10ms();
    gs_wMain_Sq_Timer--;          /* <- 2분 동안 여기 머문다 */
}
else
{
    DM_App_Main_Sq_Set_Step(MAIN_SQ_IDLE);
}
```

LCD 만 끄고 이 경로를 그대로 타면 이렇게 된다.

| | |
|---|---|
| 전력 | 2분간 깨어 있는 채로 루프를 돈다 |
| 재삽입 | 사용자가 다시 꽂아도 **2분간 반응이 없다** |

[10:16] 의 "사용자가 다시 꽂으면 동작한다" 가 **2분 뒤에나** 성립한다.
사용자는 그사이 기기가 죽었다고 본다. **목적과 정반대다.**

> 10-19 에 겪은 "에러 낸 다음 다시 꽂기 전에 한번 재워야 하나" 가 같은 문제였다.

#### 세 갈래

| 상황 | 가야 할 곳 | 화면 | 대기 |
|---|---|---|---|
| QC 구간(증가 후 1~5), 초기 광학 이상 | `ERROR_WAIT` | 에러 표시 | 2분 |
| **사용자 구간(증가 후 6 이상), 초기 광학 이상** | **`IDLE` 직행** | **없음** | **없음** |
| 정상 | 다음 단계 | — | — |

`Enter_Error()` 를 **부르지 않고** `DM_App_Main_Sq_Set_Step(MAIN_SQ_IDLE)` 로 바로 보낸다.

#### 기록은 따로 남겨야 한다

> [03:16] "디스[플레이에] 에[러] 표시 하지 말고 **내[부]에 에[러] 기[록]해 [두]는 거지.**"

`ERROR_WAIT` 가 하던 일 중 **EEPROM 저장은 살려야 한다.**

```c
/* Error_Wait_Step_Handler() 가 첫 진입 때 하던 것 */
DM_App_Rom_Set_ErrorCode(gs_bErrorCode);
DM_App_Rom_Set_ErrorStep(gs_bErrorSequence);
DM_App_Main_Sq_Save_Result_To_Rom(bSaveIndex);
```

IDLE 직행 경로에서도 이것들을 부르고 가야 한다.
안 그러면 **회수했을 때 아무 기록이 없다** — 이 지시의 목적이 무너진다.

### ④ QC 재시작 — EEPROM 전체 초기화 명령 (USART)

> [00:56] "혹시 [USART] 커[맨드]에 ... **인서트 [카운트] 리[셋]하는 거 커맨드 [있어]?**
> — **테스트하[다 보면] 다섯 번 [넘어]간다?**"
> [01:24] "**초기화할 수 있는 방법이 있는 게 좋을 것 같다.**"

**QC 구간은 증가 후 1~5이므로 여섯 번째 관문 통과부터 사용자 모드다.** QC를 다시 시작하려면 아래 초기화를 명시적으로 실행한다.

#### 이름을 "Insert Count 초기화" 로 두면 안 된다

카운트만 0 으로 돌리면 **나머지가 그대로 남아 서로 맞지 않는다.**

| | Insert Count 만 0 으로 돌리면 |
|---|---|
| QC 기준값 | 이전 기기 값이 남는다 |
| 결과 레코드 | 이전 검사 이력이 남는다 |
| 덤프 위치 | 이전 위치를 가리킨다 |

> 덤프 위치와 Insert Count 가 다른 것 **자체는 모순이 아니다.**
> 244번지를 따로 둔 이유가 Insert Count 로 역산하면 안 되기 때문이었다(10-19).
> 함께 지우는 이유는 모순 때문이 아니라 **"이전 이력을 지우고 새로 시작한다"는 정책** 때문이다.

→ 명령의 이름과 뜻을 **「QC 재시작 — EEPROM 데이터 초기화」** 로 정의한다.

#### 지우는 범위

**"전부 0" 이 아니다.** 항목마다 정해진 초기값으로 되돌린다.

| 항목 | 자리 | 초기값 | 비고 |
|---|---|---|---|
| Insert Count | 0 | `0` | |
| Test Complete Count | 1 | `0` | 사용 제한 해제. 남기면 QC 중 `ERROR_OVER_USED` 가 난다 |
| Error Step / Code | 2, 3 | `0` | |
| StickPtrData | 4~19 | `0` | `Get_StickPtrData()` 가 FF 를 0 으로 정리하는 규칙과 맞춘다 |
| 결과 레코드 6칸 | 20~211 | `0` | |
| **QC 기준값** | **212~219** | **`0xFF`** | **미기록 상태로 둬야 한다.** 아래 참조 |
| 덤프 위치 | 244 | `0` | |
| 헛깨어남 범위 | 248~251 | `0xFF` | 공장 출하 상태. 읽을 때 최댓값이 0 으로 정리된다 |

> **QC 기준값만 `0xFF` 인 이유** — [14:56] "[덤프] 딱 찍어[봤]는데 **[기록]도 없고**" 가
> 미기록 상태를 구별해야 한다. 미기록만으로 QC 미수행을 단정하지 않는다. 0 으로 채우면 "QC 해서 0 이 나왔다" 와 섞인다.

#### RAM 도 함께 지운다

**EEPROM 만 지우면 RAM 에 남은 옛 값이 다시 저장된다.**

```c
/* DM_Main_Sq_App.c */
static uint8_t gs_bStickInsertCnt = 0;
static uint8_t gs_bTestCompleteCount = 0;
```

기기는 Halt 만 하므로 RAM 이 유지된다(→ 10-19 「상태 이월」과 같은 모양).
기존 `R` 명령이 이미 둘 다 지우고 있다.

```c
void DM_App_Main_Sq_Reset_TestCompleteCount(void)
{
    gs_bTestCompleteCount = 0;              /* RAM */
    DM_App_Rom_Set_TestCompleteCount(0);    /* EEPROM */
}
```

새 명령도 같은 꼴로, **관련 RAM 상태를 모두** 되돌린다.

#### 7칸 → 6칸 전환 작업 절차

**옛 레코드의 7번째 칸(212~243)이 QC 기준값 자리와 겹친다.**
그 자리에 남아 있는 것은 옛 레코드의 앞부분, 곧 **배율 네 개**(32, 33 같은 값)다.

```
1. 기존 덤프를 CSV 로 백업한다          <- 지우기 전에 자료를 남긴다
2. 새 펌웨어(6칸)를 굽는다
3. QC 재시작 명령을 실행한다            <- 반드시 검사 전에
4. 덤프를 뽑아 초기 상태를 확인한다
5. QC 를 시작한다
```

> **3번을 빠뜨리고 검사를 시작하면 안 된다.** 옛 레코드를 QC 기준값으로 오인할 수 있다.

#### ⚠ 한계 — 초기화를 빠뜨린 기기를 펌웨어가 가려내지 못한다

**작업자가 초기화를 보장한다는 전제** 위에서만 깔끔하다.

> **범위 검사로 판별하려던 안은 폐기했다 (10-22).**
>
> "QC 기준값이 FF 도 아니고 1,500~3,900 도 아니면 초기화를 안 한 기기다" 로 가려 했으나 **틀렸다.**
>
> | 반례 | |
> |---|---|
> | 7·9번은 실측이 **4** 였다 | 정상적으로 저장된 QC 기록인데 범위 밖이다 |
> | 옛 값이 우연히 범위 안이면 | 통과한다 |
> | 옛 7번째 레코드가 비어 있었으면 | FF 라 못 잡는다 |
>
> 더 나쁜 것은, **범위 밖이라고 자동 초기화하면 보존하려던 불량 증거를 지운다.**
> 이 기능의 목적("낮은 값으로 나간 기기의 증거를 남긴다")을 정확히 반대로 수행한다.
>

## 착수 전에 확인할 것 — 2026-10-22 정리됨

- [x] **최초 5회는 QC: 증가 후 카운터 1~5, 6 이상은 사용자 구간.** 녹음의 0부터 센 회차와 구현 카운터를 구분한다.
- [x] **IDLE의 초기 CH3 관문 통과 직후 1 증가.** 초기 실패는 제외하고 증가 이후 실패는 해당 회차에 포함한다.
- [x] **254에서 포화.** FF 재해석에 따른 QC 재진입을 막고, 결과 저장은 독립적으로 여섯 칸을 순환한다.
- [x] **QC 재시작 시 기준값도 FF로 초기화.** ④절의 EEPROM·RAM 초기화 정책을 적용한다.
- [x] **범위는 1,500~3,900** 이 맞다. 녹음의 "1,600" 은 받아쓰기 오류다
- [x] **판정 방법은 기존 관문 두 개 그대로.** 새 판정을 넣지 않는다
- [x] **EEPROM 자리가 모자라면 레코드 칸을 줄인다** — 명확히 지시하셨다

- [ ] 증가 이후 실패도 한 회로 세며, 다음 재삽입에서 중복 증가하지 않는지 확인한다.
