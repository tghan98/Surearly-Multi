## 왜 이 작업을 하나

2단계에서 배율 방식이 성립한다는 것까지 확인했고(포화 없음, 여유 10%, 편차 0.2%),
2026-09-28 추가 지시로 **기준값이 모두 확정**됐다.

| 항목 | 확정값 |
|---|---|
| 양품 구간 | **1,500 ~ 3,900** (벗어나면 기계 에러) |
| 튜닝 목표값 | **1,500** |
| 필터 | 20샘플 정렬 → 위아래 2개씩 제외 → **중앙 16개 평균** |
| 배율 | `목표값 × 100 ÷ 측정값` (정수), 적용은 `÷ 100` |

지금까지는 진단 루틴으로만 측정했고 **본 광학 코드는 여전히 on-time 방식**이다.
이제 확정값을 본 코드에 반영한다.

## 무엇을 바꾸나

### 1. 필터 — 합계에서 평균으로

`DM_App_Optic_Measure()`의 반환을 **중앙 16개 평균**으로 바꾼다.

```
현재 : 20샘플 정렬 → 상하 3개씩 제외 → 중앙 14개 합계  (최대 약 57,330)
변경 : 20샘플 정렬 → 상하 2개씩 제외 → 중앙 16개 평균  (0 ~ 4,095)
```

이것으로 측정값이 단일 샘플 스케일이 되어, 확정된 1,500·3,900과 직접 비교할 수 있다.
채널 변경 후 **첫 변환 버림**도 함께 추가한다(현재 진단 루틴에만 있음).

### 2. on-time 잔재 제거

- `DM_App_Optic_Measure()`의 `wOnTime_us` 인자
- `OPTIC_ONTIME_DEFAULT / MAX / X1 / X2`
- `DM_HW_Drv_Delay_us()`, `DELAY_US_CAL`
- `MeasureInitialStick()`의 `awPWM_Set[2] = {199, 399}`
- `TuneTargetADC()`의 0~399 클램프, P제어 5회 반복

LED ON 후 대기는 **20ms 안정화**(`SystemSleep_10ms() × 2`)로 고정한다.

### 3. 배율 튜닝 구현

```c
/* 튜닝 시점 */
배율 = (uint16_t)((uint32_t)1500 * 100 / 측정값);   /* 0~100, 정수 */

/* 측정 적용 시점 */
최종값 = Cal_Ratio(측정값, 배율);                    /* = 측정값 * 배율 / 100 */
```

`Cal_Ratio()`는 `DM_Utill.c`에 이미 있고 내부가 uint32이므로 **추가 코드가 없다.**

**방어는 2중으로 한다.**

**1차 — 양품 구간 검사.** `MeasureInitialStick()`이 튜닝보다 먼저 실행되어 측정값을
1,500~3,900과 비교하고, 벗어나면 기계 에러로 빠진다. 하한이 목표값과 같으므로 이 검사를
통과한 시점에 배율은 이미 100 이하다. **별도의 `ERROR_OPTIC_FAIL_CHx` 경로는 두지 않는다.**

**2차 — 코드 가드 두 개.**

```c
if (측정값 == 0) { /* 기계 에러 처리 */ }        /* 0 나눗셈 방지, 필수 */

배율 = (uint16_t)((uint32_t)1500 * 100 / 측정값);
if (배율 > 100) { 배율 = 100; }                  /* 상한 clamp */
```

clamp가 필요한 이유는 **범위 검사와 튜닝이 서로 다른 측정을 쓰기 때문**이다.
범위 검사를 1,501로 겨우 통과한 개체가 튜닝 측정에서 1,499를 읽을 수 있다(반복성 ±0.1%).
몇 바이트짜리 보험이며, **clamp가 걸린다는 것 자체가 비정상 신호**이므로 주석으로 남긴다.

**버퍼 처리** — 2점 측정 폐지로 채널당 1값, 총 4워드가 된다. 그러나
`gs_awInitialStickPtr[8]`과 EEPROM offset 4~19(16바이트) 레이아웃은 **그대로 유지**한다.
**앞 4워드에 측정값, 뒤 4워드는 0으로 채운다.** `EEPROM_UART.md`의 PC GUI 파싱을
건드리지 않기 위함이며, 0은 미사용임이 명확히 드러나는 값이다.

### 4. 상수 교체 (`Parameter_define.h`)

| 상수 | 현재 | 변경 |
|---|---|---|
| `_nTAGET_LIGHT` | 800 | **1500** |
| `OPTIC_INITIAL_MIN_100` | 1800 | **1500** |
| `OPTIC_INITIAL_MAX_100` | 4200 | **3900** |
| `OPTIC_INITIAL_MIN/MAX_50` | 900 / 2100 | **삭제** (2점 측정 폐지) |
| `OPTIC_STICK_REMOVE_THRESHOLD` | 1000 | **약 2600** (실측 근거: 스틱 없음 1,500 / 있음 3,700). **배율을 적용하지 않은 원본값과 비교할 것** — 배율 적용 후에는 모든 채널이 1,500 부근으로 모여 스틱 유무 구분이 사라진다 |

### 5. ADC 설정 복원

- `DM_HW_Drv_ADC_Init()`의 샘플링을 **384사이클**로 복원, 주석과 코드 일치
- `ADC_READ_TIME_US`(현재 14, 16사이클 기준) → **잠정 198**
  - 기존 14가 `(16 + 12) ÷ 2MHz`로 나온 값이므로, 같은 식으로 `(384 + 12) ÷ 2MHz = 198`
  - **이 상수는 ADC 1회 읽기마다 틱에 더해지고, 측정 1회당 20번 읽으므로 측정당 약 4ms다**
  - 레거시 실측값은 220이었으나 그것은 wfi/EOC 인터럽트 지연을 포함한 값이고, 현재는 폴링이다
  - **주석에 "잠정값 — 4단계 5분 대기 재측정에서 확정" 명시할 것**
- **폴링 루프에 타임아웃 추가** — 현재 무한 대기라 EOC가 안 뜨면 LED를 켠 채 Halt로
  복귀하지 못한다. 코인셀 제품이므로 안전 항목
- 죽은 코드 제거: `ADC1_COMP_IRQHandler`, `ADC_SetConvDone/GetConvDone/ClearConvDone`

### 6. 진단 루틴 제거

`DM_App_Optic_RunDiagnostic()`과 `g_awDiag_*` 전역, `User_Main.c`의 호출부를 제거한다.

### 건드리지 않는 것

- **저전력 구조** — Tick wake-up, `while` + `wfi`, Halt 복귀 경로 (지시 4)
- `CalculateIntensity()`, `Cal_Ratio()` 등 검증된 유틸
- LED↔채널 매핑, ADC 채널 매핑
- LCD 구동 로직

## 어떻게 확인할 건가

| 단계 | 확인 방법 | 합격 기준 |
|---|---|---|
| 빌드 | IarBuild Debug | 에러 0, 경고 0 |
| 코드 사이즈 | `.map` 하단 3줄 | Flash 8,192B 이내. TIM2·`Delay_us`·진단 루틴 제거분만큼 줄어야 정상 |
| 측정값 스케일 | 디버거 Watch로 `Measure()` 반환 확인 | **3,700 부근** (52,000이 나오면 평균 변경 실패) |
| 범위 판정 | 스틱 삽입 상태 초기 측정 | 4채널 모두 1,500~3,900 통과 |
| 배율 | 디버거 Watch | **약 41** (0.41) |
| 배율 적용 후 | 최종값 | **1,500 부근** |
| 폴링 타임아웃 | 코드 리뷰 | 무한 루프가 남아 있지 않을 것 |
| 0 나눗셈 가드 | 코드 리뷰 | `측정값 == 0` 분기가 있을 것 |
| 초기 버퍼 | 디버거 Watch `gs_awInitialStickPtr` | 앞 4개는 측정값, **뒤 4개는 0** |

여기까지 통과하면 `_DEBUG_LCD_SEQ_ONLY = 0`으로 4단계 전체 시퀀스 검증으로 넘어간다.

## 미리 적어두는 주의점

- **1,500~3,900은 배율을 곱하기 전 원본값 기준**이다. 곱한 뒤에는 전부 1,500 부근으로
  모여 범위 검사가 무의미해진다. 코드 주석에 명시할 것
- `Save_Result_To_Rom()`의 "PWM 값 4워드"가 **"배율 값 4워드"**가 된다.
  레이아웃·바이트 수는 그대로이므로 `EEPROM_UART.md` 문구만 갱신
- `CalculateIntensity()`는 제수가 약 6,553을 넘으면 내부에서 값이 잘린다.
  목표 1,500에서는 안전하나, 스케일을 키우는 변경을 할 때 반드시 재검토
