## 왜 이 작업을 하나

4단계에서 배율 방식이 보드에서 동작하는 것을 확인하고 중간보고한 결과,
2026-09-28 오후 상급자 2차 지시가 나왔다. **기준서 1장 `추가 지시 (2026-09-28 오후)` 참조.**

보고한 실측값은 초기 측정 3,653 / 3,567 / 3,549 / 3,468 → 배율 41 / 42 / 42 / 43
→ 적용 후 **1,492 / 1,488 / 1,482 / 1,482** 이었다.

여기서 두 가지가 지적됐다.

- **목표 1,500은 양품 구간 하한(1,500)과 같아 여유가 없다** → 1,200으로 내린다
- **적용 후 값이 목표에 정확히 닿지 않는다**(1,482~1,492) → 통과 기준에 여유가 필요하다

그리고 배율 방식에서는 튜닝해도 점등 조건이 바뀌지 않으므로,
**Empty를 따로 잴 필요가 없다**는 점도 확인됐다.

## 무엇을 바꾸나

### 1. Empty 측정 생략 — 측정 1회로 통합

`DM_App_Optic_MeasureEmptyPTR()`이 4채널을 다시 재는 대신,
**`초기측정값 × 배율`로 계산**한다.

**함수를 개명한다** — 더 이상 측정하지 않으므로 `Measure`라는 이름이 실제와 어긋난다.

```c
/* 기존 */
uint8_t DM_App_Optic_MeasureEmptyPTR(uint16_t* pBuffer);

/* 변경 */
uint8_t DM_App_Optic_CalcEmptyPTR(const uint16_t* pInitBuffer, uint16_t* pBuffer);
```

```c
uint8_t DM_App_Optic_CalcEmptyPTR(const uint16_t* pInitBuffer, uint16_t* pBuffer)
{
    static uint8_t bCh;

    for (bCh = 0; bCh < (uint8_t)OPTIC_CH_MAX; bCh++)
    {
        /* Zero gain means TuneTargetADC() has not run. Fail loudly rather than
           writing a plausible-looking number. Not reachable on the normal path
           (gain lands in 31..80), only if the call order is broken. */
        if (gs_wOptic_Gain[bCh] == 0)
        {
            return (uint8_t)(FAIL_OPTIC_CH0 + bCh);
        }

        pBuffer[bCh] = Cal_Ratio(pInitBuffer[bCh], gs_wOptic_Gain[bCh]);
    }

    return OPTIC_SUCCESS;
}
```

**반환형은 `uint8_t`를 유지한다.** 이 함수는 배율을 전역에서 읽으므로 **호출 순서에
의존**하는데, 0-검사가 그 위반을 잡아낸다. 실제 분기가 있는 검사이므로
"항상 성공만 반환하는 껍데기"와는 다르다.

**호출부**(`DM_Main_Sq_App.c` 284행)는 `OPTIC_ERR_STICK_REMOVED` 분기를 **삭제**하고
(스틱 확인이 사라져 절대 반환되지 않음) `bResult != OPTIC_SUCCESS` 분기만 남긴다.
`TuneTargetADC()` 호출부와 같은 형태가 되어 두 함수가 대칭이 된다.

- PWM 시절에는 튜닝 후 듀티가 바뀌어 재측정이 **필수**였으나, 배율 방식은 100% 고정이라
  조건이 변하지 않는다. 실측 차이는 **0.3%**였다
- **LED 점등이 채널당 1회 + 스틱 확인 1회 = 8회 줄어든다**
- 함수 시그니처에 초기 버퍼를 넘기도록 바꿔야 한다. 호출부는 `DM_Main_Sq_App.c` 284행
- 채널별 `Check_StickPresent()`도 함께 제거한다 — 측정이 사라져 감시할 구간이 없다

> **주의** — 이 변경으로 EEPROM 덤프의 `ET/EBT/EBC/EC`가 네 채널 모두 목표값 근처로
> 거의 같게 찍힌다. 기준서 8장 확인 항목.

### 2. 목표값 1,500 → 1,200

`Parameter_define.h`의 `_nTAGET_LIGHT`를 **1200**으로.

양품 구간(1,500~3,900)은 **그대로 둔다.** 목표값과 구간 하한은 별개 기준이다.

### 3. 배율 계산을 반올림으로

```c
/* 기존 — 절삭 */
gs_wOptic_Gain[bCh] = (uint16_t)((uint32_t)wTargetADC * OPTIC_GAIN_SCALE / pInitBuffer[bCh]);

/* 변경 — 반올림 */
gs_wOptic_Gain[bCh] = (uint16_t)(((uint32_t)wTargetADC * OPTIC_GAIN_SCALE
                                  + pInitBuffer[bCh] / 2) / pInitBuffer[bCh]);
```

절삭이면 목표 1,200 기준으로 결과가 최대 **32** 낮게 나와 통과 기준 ±25를 벗어난다.
반올림하면 오차가 절반으로 줄어 들어온다. 근거 표는 기준서 1장.

### 4. 통과 기준 `목표 ± 25` 추가

`Parameter_define.h`에 신설한다.

```c
#define OPTIC_TUNED_TOLERANCE   25   /**< Allowed deviation of the gain-applied value from the target */
```

반올림을 써도 이론상 최대 오차가 약 20.5(측정값 3,900 부근)이므로 25로 잡았다.

### 5. 판정 2단계

| 순서 | 검사 대상 | 기준 |
|---|---|---|
| ① | 튜닝 **전** 원본 측정값 | `OPTIC_INITIAL_MIN/MAX_100` (1,500 ~ 3,900) |
| ② | 배율 **적용값** | `목표 ± OPTIC_TUNED_TOLERANCE` (1,175 ~ 1,225) |

②를 벗어나면 `FAIL_OPTIC_CH0 + bCh`로 처리한다.

**튜닝 후 재측정해서 다시 확인하는 더블체크는 하지 않는다** — 전력 낭비다.

### 건드리지 않는 것

- **저전력 구조** — Tick wake-up, `while` + `wfi`, Halt 복귀 (지시 4)
- 양품 구간 1,500 ~ 3,900
- 필터(상하 2개씩 제외·중앙 16개 평균), 20ms 안정화
- `OPTIC_STICK_REMOVE_THRESHOLD` — 원본값 비교 유지
- EEPROM 레코드 구조 — **6단계에서 다룬다**

## 어떻게 확인할 건가

중단점은 `DM_App_Optic_TuneTargetADC()`의 `return OPTIC_SUCCESS;`.

| 항목 | 기대값 | 어긋나면 |
|---|---|---|
| 빌드 | 에러 0, 경고 0, Flash 8,192B 이내 | — |
| `gs_awInitialStickPtr[0~3]` | 3,000대 | 52,000이면 필터 변경 실패 |
| `gs_wOptic_Gain[0~3]` | **32 ~ 35** | 반올림 미적용 시 한 단계 낮게 나옴 |
| `gs_awEmptyBand_LowData[0~3]` | **1,175 ~ 1,225** | 범위 밖이면 ±25 재검토 |
| Empty가 계산값인지 | 초기값 × 배율 ÷ 100과 **정확히 일치** | 다르면 재측정이 남아 있는 것 |
| 0-검사 존재 | `CalcEmptyPTR()`에 `gs_wOptic_Gain[bCh] == 0` 분기 | 코드 리뷰로 확인 |
| 함수 개명 | `MeasureEmptyPTR` 잔재 없음 | `grep`으로 확인 |

마지막 항목이 중요하다. 재측정을 없앴으므로 **계산 결과와 한 치도 다르지 않아야** 한다.
1 이상 차이가 나면 어딘가에서 아직 측정하고 있는 것이다.

## 미리 적어두는 주의점

- 반올림 식에서 분자가 uint32를 넘지 않는지 확인 (1200×100 + 1950 = 121,950 — 여유 충분)
- 개명·반환형·0-검사는 1항에서 확정했다 (2026-09-29 착수 검토 반영)
- 목표값이 바뀌면 `OPTIC_STICK_REMOVE_THRESHOLD`(약 2,600)는 **영향 없다** — 원본값 기준이다
- 5단계는 측정·판정 로직만 다룬다. **EEPROM 구조와 PC UI는 6단계**다

| 측정 시점 | 앞(T) → 뒤(C) | 기울기 |
|---|---|---|
| 2026-09-23 (진단 루틴) | 3,718 → 3,690 | −0.8% |
| 2026-09-28 (4단계) | 3,653 → 3,468 | −5.1% |

**오늘 기울기가 빈 챔버와 같은 수준까지 벌어졌다.**

> **스틱 동일성 — 기록 없음.** 09-23은 "스틱 A / 신품 스틱 B"로 명시돼 있으나,
> 09-28·09-29에 어떤 스틱을 썼는지는 기록하지 않았다. 따라서 위 표의 차이에는
> 안착 상태 외에 **스틱 자체의 개체차가 섞여 있을 수 있다.**

다만 **스틱 교체와 무관한 증거가 하나 있다.** 09-28 하루에 두 번 삽입했는데 기울기가 달랐다.

| 09-28 | 측정값 | 기울기 |
|---|---|---|
| 1회차 | 3,590 → 3,314 | **−7.7%** |
| 2회차 | 3,653 → 3,468 | **−5.1%** |

같은 날 연속 두 번인데 2.6%p 차이가 난다. **삽입할 때마다 안착 상태가 달라진다**는 것은
이 비교만으로 성립한다. 유격 현상 그 자체다.

> **7단계 시험 조건** — 회복 대기시간 스윕을 할 때는 **스틱을 고정하고 대기시간만 바꿔야**
> 비교가 성립한다. 스틱을 바꾸거나 다시 꽂으면 안착 차이가 섞여 대기시간 효과를 분리할 수 없다.
> 어떤 스틱을 썼는지도 함께 기록한다.

그럼에도 네 채널 모두 양품 구간(1,500~3,900) 안에 들었고, 배율이 34~38로 보정해
최종값을 1,200 부근으로 모았다. **배율 튜닝이 유격을 흡수한다는 것이 실측으로 보인 셈이다.**

## 걸린 것 / 남은 것

### ① 착수 검토에서 문서 모순 4건이 드러났다

에이전트가 코드를 고치기 전 문서를 읽고 지적한 것들이다.

| | 내용 |
|---|---|
| 가 | `MeasureEmptyPTR()`이 측정하지 않는데 이름이 `Measure`로 남음 → 개명 |
| 나 | 판정 ②의 **위치**가 문서에 없음 → `TuneTargetADC()` 배율 계산 직후로 확정 |
| 다 | 스틱 확인 제거로 호출부 에러 분기가 **도달 불가**가 됨 → 정리 |
| 라 | 기준서 2장에 디버그 스위치 행 **중복**, 브랜치가 `stage4`로 남음 → 수정 |

### ② 반환형 판단을 한 번 뒤집었다

처음에는 "실패할 일이 없으니 `void`로" 결론냈다. 그런데 **배율 0 검사를 넣기로 한 순간
실패할 경우가 생겼다.** 함수가 이상을 알면서 조용히 넘어가는 구조가 되므로,
`uint8_t` + `FAIL_OPTIC_CH0 + bCh` 반환으로 되돌렸다.

### ③ 기준서 4-4절의 낡은 서술 3건

목표값이 1,200으로 바뀌면서 근거가 무효가 된 문장들이다. 에이전트가 찾아 알려줬고 수정했다.

- "하한(1,500)이 목표값(1,500)과 같으므로" → **"하한(1,500)이 목표값(1,200)보다 크므로"**
- "배율은 약 41" → **배율 범위표**(하한 80, 상한 31, 실측 33~38)
- "최종값 ≤ 57,330" → 합계 시절 서술이라 폐기

### 남은 것

- **`Check_StickPresent()` doc의 `Duty 100%` 표현** — PWM 잔재. 6단계에서 `PWM CH1~4` → `Gain CH1~4`와 함께 정리
- **7단계 회복 대기시간 스윕** — 기울어짐이 매번 다르다는 것이 확인됐으므로 시험 가치가 더 커졌다
- 상급자 확인 **6건** — 기준서 8장. 5단계에서 "Empty 계산값 대체의 영향"이 추가됐다

## 오늘의 교훈

**결정을 하나 바꾸면 그 결정에 딸린 판단도 다시 봐야 한다.** "실패할 일이 없으니 반환값을
없애자"고 정한 뒤 "배율 0 검사를 넣자"고 했는데, 두 번째 결정이 첫 번째의 전제를 무너뜨렸다.
되물어보지 않았다면 이상을 알면서 알리지 않는 함수가 남았을 것이다.

**문서를 고칠 때는 그 문장이 기대고 있던 숫자까지 따라가야 한다.** 목표값을 1,500에서
1,200으로 바꾸면서 "하한과 목표가 같다"는 근거, "배율 약 41", "최종값 57,330"이 모두
무효가 됐는데 한 번에 찾지 못했다. **값을 바꿀 때 그 값이 등장하는 모든 문장을 훑는 절차**가
필요하다.

> **같은 함정에 두 번 빠졌다.** 위 항목을 정리한 직후, "4단계 실측 배율"을 언급하면서
> 목표값만 5단계 값(1,200)으로 갈아끼우고 계산 규칙(절삭)은 4단계 것을 써서
> **어느 단계에도 없는 조합(32~34)**을 만들어냈다. 실제 4단계 값은 41~43이다.
>
> **배율은 측정값만의 함수가 아니라 목표값·반올림 규칙까지의 함수다.** 과거 시점의 값을
> 언급할 때는 **그 시점의 규칙 전부**를 가져와야 한다. 기준서 4-4절에 주의 박스를 넣어
> 같은 혼동이 반복되지 않게 했다.

**검증 항목은 "일치해야 한다"로 쓸 수 있으면 그렇게 쓴다.** "1,175~1,225 사이"보다
"계산값과 정확히 일치"가 훨씬 강한 검증이었다. 범위 검사였다면 재측정이 조금 남아 있어도
통과했을 것이다.

**기울어짐은 세 번 재서야 성격이 보였다.** 한 번(−0.8%)은 정상, 두 번(−5%)은 의심,
세 번(−10%)에서야 "매번 다르다"가 확정됐다. **한 번의 측정으로 성격을 단정하지 않는다.**

**측정할 때 조건을 같이 적어두지 않으면 나중에 비교가 안 된다.** 09-28·09-29에 어떤 스틱을
썼는지 적지 않아, 기울기 차이의 원인을 안착과 개체차로 나눌 수 없게 됐다. 다행히 09-28
하루 안의 두 번 비교로 결론은 건졌지만, **측정값만 적고 조건을 빠뜨린 것이 원인**이었다.

## 끝맺음 한 문장

재측정을 없앤 것이 숫자로 증명됐고, 스틱이 10% 기울어 앉은 상태에서도 배율이 최종값을
목표 부근으로 모으는 것을 확인했다.
