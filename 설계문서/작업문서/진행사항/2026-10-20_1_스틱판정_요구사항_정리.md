## 3. 지시별 현황

### ① 멤브레인 vs 플라스틱 — **계산 완료. 추가 측정 불필요**

10-02 실측(동일 기기·동일 스틱 10회 반복, CH3 **원본값**)으로 바로 나온다.
→ `2026-10-02_검사오류2_부분삽입_광학값실측.md`

**상태 사이의 편차**

| 비교 | 차이 | 정상 대비 |
|---|---|---|
| 플라스틱 701 vs 정상 멤브레인 3,368 | 2,667 | **79.2% 낮음** |
| 살짝 빠짐 3,618 vs 정상 멤브레인 3,368 | 251 | 7.4% 높음 |

**구간이 겹치지 않는 여유**

| 경계 | 간격 | 정상 대비 |
|---|---|---|
| 플라스틱 최대 746 ↔ 정상 최소 3,320 | 2,574 | **76.4%** |
| 정상 최대 3,485 ↔ 살짝빠짐 최소 3,524 | 39 | 1.16% |

**각 상태의 산포 (10회)**

| 상태 | 평균 | 표준편차 | 폭 |
|---|---|---|---|
| 정상 삽입 | 3,368 | 49.8 (1.5%) | 165 (4.9%) |
| 살짝 빠짐 | 3,618 | 41.7 (1.2%) | 131 (3.6%) |
| 플라스틱 | 701 | 26.1 (3.7%) | 72 (10.3%) |

**답** — 플라스틱 구분은 **79.2% 편차**로 이미 갈린다. 두 구간 사이가 정상값의 76.4%만큼
비어 있어 문턱값을 그 안 어디에 두든 틀리지 않는다. 현재 문턱값 2,600도 그 안에 있다.

**다만 "빠짐"에 두 단계가 있고 방향이 반대다.**

```
   701              3,368   3,618
 ───●────────────────●───────●───
 플라스틱            정상   살짝빠짐
```

- 더 빼면 플라스틱이 올라와 값이 **뚝 떨어진다** (701)
- 살짝만 빠지면 멤브레인이 아직 센서 위에 걸쳐 있어 값이 **조금 올라간다** (3,618)

현재 판정은 `값 < 문턱값` 뿐이라 **아래쪽만 본다**(단방향 판정).
→ 701은 잡고, 3,618은 못 잡는다. 이쪽이 ②와 함께 11단계로 간다.

### ② 기본 / 젖은 / 발색 — **숫자는 있으나 연속 측정이 없다**

CH3 **배율축** 값이다. 같은 축임을 코드로 확인했다 —
`DM_Main_Sq_App.c` 419·628행과 `Check_StickPresent_Scaled()`가 같은 식을 쓴다.

```c
Cal_Ratio(DM_App_Optic_Measure(OPTIC_CH_3), DM_App_Optic_GetGain(OPTIC_CH_3))
```

| 상태 | CH3 배율축 | 출처 |
|---|---|---|
| 기본 (마른 멤브레인) | 1,183 ~ 1,213 | 덤프 `EC` 열 |
| 발색 후 | 929 ~ 982 | 덤프 `RC` 열 |
| 젖은 순간 (최저) | 621 ~ 800 | 10-19·10-20 임시 계측 |
| (스틱 없음) | 420 ~ 488 | 참고 |

젖으면 빛이 덜 돌아와 값이 뚝 떨어지고(621), 액이 퍼지면서 회복해 발색 상태(929)에 자리 잡는다.

| 경계 | 간격 |
|---|---|
| 발색 982 ↔ 기본 1,183 | 201 |
| 젖음 800 ↔ 발색 929 | 129 |
| 없음 488 ↔ 젖음 621 | 133 |

①의 2,574와 비교하면 전부 좁다. 쓸 수는 있으나 여유가 작다.

**막혔던 것** — 위 숫자는 한 회차를 끝까지 따라가며 잰 것이 아니었다.
기본·발색은 여러 기기의 덤프에서, 젖음은 임시 계측에서 따로 가져온 값이었다.

> **해결됨 (당일 오후).** 세 값 중 **둘은 이미 덤프에 찍히고 있었다**(`EC`, `RC`).
> 추가로 필요한 것은 젖음 하나뿐이었고, 전날 지운 `g_DbgMinVal` 4줄이 그대로 들어맞았다.
> 3대 × 3회 측정 결과 **발색 79.3% / 젖음 60.9%, 간격 8.7%p 로 겹치지 않는다.**
> → `2026-10-20_2_3상태_편차측정.md`
>
> 이 절에서 "구조 변경이 먼저"라고 적은 것은 **틀렸다.** 구조 변경이 필요한 것은
> ②가 아니라 ①의 살짝 빠짐 쪽이다.

### ③ SW1 오검출 — **방어는 이미 있다. 계수가 없다**

실제 발생 사례는 없다. 가정에 대한 지시다.

**방어는 이미 들어가 있다.** `DM_Main_Sq_App.c` 194행.

```c
    if (DM_App_Optic_Check_StickPresent())   /* CH3 원본값 >= 2600 */
    {
        /* LCD 시퀀스 시작 */
    }
    else
    {
        /* Spurious wake or stick pulled back out immediately: ... */
        DM_App_Main_Sq_Set_Step(MAIN_SQ_IDLE);   /* 다시 잠듦 */
    }
```

주석에 `Spurious wake`(헛깨어남)라고 적혀 있다. SW1이 잘못 눌려 깨어나도 광학값이
아니면 그대로 다시 잔다. **7·9번이 "LCD 미출력"으로 보였던 것이 이 `else` 경로다 —
방어가 작동한 사례다.**

**약한 데 두 군데**

**ⓐ 깨우는 신호에 필터가 없다.**
`DM_HW_Drv.c` 329행이 PB1의 떨어지는 모서리 하나에 반응한다.

```c
EXTI_SetPinSensitivity(EXTI_Pin_1, EXTI_Trigger_Falling);
```

인터럽트 처리기(`User_Main.c` 129행)는 **깃발만 지우고 아무것도 하지 않는다.**
신호가 진짜인지 확인하지 않으므로 노이즈 한 번에 그대로 깨어난다.
다만 광학 관문이 받아내므로 피해는 **전지 소모**뿐이다.

**ⓑ 되돌아가는 길이 비어 있다.**
`else` 로 가면 그냥 `MAIN_SQ_IDLE` 로 돌아간다. **몇 번 헛깨어났는지 아무도 세지 않는다.**
노이즈가 계속 들어오면 깨어남–측정–잠듦을 끝없이 반복한다.
기기는 겉보기에 멀쩡한데 전지만 말라가고, **그런 일이 있었는지 나중에 알 방법이 없다.**

> **계측 사각지대** — 일어난 일이 어디에도 기록되지 않아, 사후에 확인할 수 없는 상태.

**할 일** — EEPROM에 헛깨어남 횟수를 세는 칸 하나. **245번지가 비어 있다**
(244번지가 덤프 위치). 덤프에 실으면 현장 기기 회수 시 "이 기기는 헛깨어남이 300번
있었다"를 볼 수 있다.

| | 기준서 7장 계획 | 실제 브랜치 |

기준서가 계획했던 7·8단계(회복 대기시간, 전체 시퀀스 검증)는 **아직 하지 않았다.**

## 5. 다음 단계

| 단계 | 내용 | 지시 | 길이 | 상태 |
|---|---|---|---|---|
| **10단계** | 상태 구분 편차 정리 | ①②③ | 반나절 | ✅ 당일 완료 |
| **11단계** | 살짝 빠짐 검출 | ①(살짝 빠짐) | 며칠 | 착수 전 |

> **당초 가름이 틀렸다.** ②를 11단계(며칠)로, ③의 헛깨어남 계수를 10단계로 넣었으나
> 실제로는 ②가 반나절이었고(세 값 중 둘이 이미 덤프에 있었다),
> ③은 계수를 보류하기로 해 코드 변경이 없어졌다.
> 11단계에 남은 것은 **살짝 빠짐**뿐이다.

**10단계를 먼저 하는 이유** — 둘 다 지금 구조 그대로 할 수 있다.
①은 계산이 이미 끝나 보고만 하면 되고, ③은 EEPROM 칸 하나와 세는 코드뿐이다.

**11단계가 긴 이유** — 재기 전에 **구조를 바꿔야 한다.** 세 겹으로 막혀 있다.

1. 세 번째 덤프 덩어리(T/BT/BC/C, EEPROM 4~19)는 **한 칸짜리**라 최신 1회차만 남는다
2. 그마저도 `DM_Optic_Handle_App.c` 181·197행의 관문에 걸리면 저장 자체가 안 된다
3. → **실패한 회차의 원본값은 아예 남지 않는다.** 살짝 빠짐은 대개 실패로 끝나므로
   정확히 보고 싶은 회차가 기록되지 않는 구조다
4. 레코드 16칸도 전부 차 있다
