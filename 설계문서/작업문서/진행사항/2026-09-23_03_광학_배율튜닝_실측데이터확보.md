# 2026-09-23_03_광학_배율튜닝_실측데이터확보

## 한 줄 요약

> 진단 루틴으로 광학 ADC를 실측해, 김효신 수석님 지시대로의 배율 튜닝 방식이 성립한다는 것과 필요한 설계값의 근거를 확보했습니다.

## 1. 뭘 하려던 거였나 (배경)

김효신 수석님 지시로 광학 튜닝 방식이 확정됐습니다.

- LED는 GPIO로 100% 점등만 한다 (PWM 없음)
- LED ON 후 ADC 측정까지 20ms 안정화한다
- 밝기 조절은 점등시간이 아니라, 읽은 측정값에 배율을 곱하는 소프트웨어 방식으로 한다
- 저전력 설계 구조는 건드리지 않는다

그런데 이 방식이 실제로 되는지는 숫자를 본 적이 없어 알 수 없었습니다. 100% 점등에서 ADC가 천장(4095)에 닿아버리면, 배율을 곱해도 눌린 값은 복구되지 않기 때문입니다.

그래서 본 광학 코드는 건드리지 않고, 측정만 하는 임시 진단 루틴을 만들어 확인했습니다.

## 2. 뭘 했나

### 2.1 진단 루틴 작성

`DM_App_Optic_RunDiagnostic()`을 추가하고 `_DEBUG_LCD_SEQ_ONLY=1`일 때 `User_Main_Init()` 끝에서 1회 실행하도록 했습니다. 결과는 전역 volatile 배열에 담아 디버거 Watch로 읽었습니다. USART는 쓰지 않았습니다.

측정 항목은 다섯 가지입니다.

- A: LED 100% 점등 후 20ms 대기 측정값 (포화 확인)
- B: LED OFF 상태 암전류 dark
- C: 대기시간 0/10/20/30/40/50ms 스윕 (실제 RC 시정수 확인)
- D: 채널당 5회 반복성
- E: ADC 16사이클과 384사이클 비교

구현 시 지킨 조건입니다.

- ADC 채널 변경 후 첫 변환은 버리고 이후 20개를 취득 (레거시 `BSP_ADC.c`와 동일)
- 20ms 대기는 `DM_HW_Drv_SystemSleep_10ms()` 2회 호출로 구현 (busy-spin 없음)
- dark도 측정값과 동일한 필터(20샘플 정렬 후 중앙 14합) 적용
- E는 런타임에 `ADC_SamplingTimeConfig()`를 다시 호출해 비교하고, 끝난 뒤 초기값으로 복원

### 2.2 세 가지 조건에서 측정

스틱 미삽입, 스틱 A 삽입, 신품 스틱 B 삽입 세 조건에서 각각 측정했습니다.

처음에는 스틱 없이 측정했는데, 그 상태로는 빈 삽입구를 잰 것이라 포화 여부를 판단할 수 없었습니다. 흰 멤브레인이 들어가면 반사광이 크게 늘기 때문입니다. 스틱을 넣고 다시 측정해 실제 사용 조건의 값을 확보했습니다.

항목별 측정 조건은 다음과 같습니다. C/D/E는 회로 특성 확인이 목적이라 스틱 미삽입 조건에서 측정했습니다.

| 항목 | 측정 조건 |
|---|---|
| A. 안정화 측정값 | 스틱 미삽입 / 스틱 A / 신품 스틱 B |
| B. 암전류 dark | A를 4채널 모두 측정한 뒤, LED OFF 상태에서 채널별로 측정 |
| C. 대기시간 스윕 | 스틱 미삽입 |
| D. 반복성 | 스틱 미삽입 |
| E. 16 vs 384 사이클 | 스틱 미삽입 |

C에서 본 값은 최종값 대비 도달률이라 시정수 자체는 스틱과 무관하지만, ADC 절대값은 스틱 유무에 따라 약 2.4배 차이가 납니다. 스틱 삽입 상태의 C/D/E는 측정하지 않았습니다.

## 3. 확인된 것 / 잘 된 것

- [x] 포화되지 않음 — 스틱 삽입 시 단일 3690~3723, 천장 4095의 약 90%
- [x] 클리핑 아님 — 채널별 값이 미세하게 달라 눌리지 않았음을 확인
- [x] 스틱 간 편차 0.13~0.24% — 신품 스틱으로 교체해도 5~9 카운트 차이뿐
- [x] 여유(372 카운트)가 스틱 간 편차(9 카운트)의 약 40배
- [x] **현재 실측 조건에서 배율 튜닝 방식 성립 확인** (온도·배터리 전압 변동에 대한 마진은 4단계에서 재확인)
- [x] 배율 약 0.81 (레거시 목표 3000 / 실측 3700)
- [x] 잔광 영향이 없는 채널 2·3에서 암전류 8~9 카운트 확인. 현재 측정 조건에서 신호 대비 0.23%이므로 dark 보정 생략, 단순 곱하기 채택
- [x] tau 4.2~4.8ms — 계산값 100k x 47nF = 4.7ms와 일치, C12~C14가 47nF인 설계와 부합 확인
- [x] 20ms는 98.7% 도달 지점으로 적절
- [x] 반복성 +-0.1%
- [x] ADC EOC 플래그 정상 동작 — `ADC_ClearFlag()` 추가 불필요
- [x] 384사이클이 16사이클보다 0.41~0.51% 높음 (4채널 모두 동일 경향) → **384 채택 결정** (코드 반영은 다음 단계)
- [x] 스틱 유무 2.4배 차이 — 스틱 감지 임계값 근거 확보
- [ ] 목표값 스케일 결정 (단일 3000 기준 vs 14합 42000 기준)
- [ ] 온도·배터리 전압 변동에 대한 포화 마진 확인 (4단계)

상세 수치는 `설계문서/작업문서/v11-배율튜닝-설계서.md` §6-1에 기록했습니다.

## 4. 걸린 것 / 남은 것

- 처음 측정을 스틱 없이 해서 한 번 다시 측정했습니다. 진단 루틴은 전원 인가 직후 실행되므로, 앞으로도 측정 전에 스틱 삽입 여부를 먼저 확인해야 합니다.
- 암전류 측정에서 채널 0, 1 값이 유독 높게 나왔습니다(단일 환산 313 / 20). B 루프는 A 루프가 끝난 직후 시작되는데, 채널 0은 A의 마지막 채널이 LED를 끄고 10ms 지난 시점에 읽힙니다. tau 4.7ms 기준 10ms 후 약 12% 잔존이라는 계산과 실측이 맞아떨어졌습니다. 채널이 뒤로 갈수록 경과 시간이 늘어 값이 떨어지며, 잔광 영향이 없는 채널 2, 3의 8~9 카운트가 진짜 dark입니다.
- `DM_App_Optic_Measure()`는 14합을 반환하는데 레거시 목표값 3000은 단일 스케일입니다. 반환값을 단일로 환산할지 임계값을 14배할지 결정해야 합니다. 기존 `OPTIC_INITIAL_MIN/MAX_*`(900~4200)도 같은 문제를 갖습니다.
- 진단 루틴은 임시 코드입니다. 본 코드 수정이 끝나면 제거해야 합니다.
- `ADC_READ_TIME_US`(현재 14)는 16사이클 기준이라, 384사이클로 되돌리면 재산출해야 합니다.

## 5. 오늘의 교훈

측정 전 검토에서 설계 오류 몇 가지가 미리 잡혔습니다. 특히 배율 식이 `(측정값 - dark) x 배율 + dark`인데 배율을 `목표값 / 측정값`으로 두어, dark가 클 경우 결과가 목표값보다 `dark x (1 - 배율)`만큼 커지는 문제가 있었습니다. 구현 후였다면 "값이 조금씩 크게 나오는데 왜지"로 한참 헤맸을 문제입니다.

측정값 스케일도 마찬가지입니다. 20샘플 중앙 14합이라 최대 57,330이고 uint16 한계에 이미 근접해 있는데, 이를 모르고 배율을 곱했다면 조용히 잘렸을 것입니다.

숫자 없이 세운 계획이 틀렸던 전날 경험(구펌웨어 on-time 759~843을 us로 오해)과 합쳐, **구현 전에 재고 검토한다**는 순서가 유효하다는 것이 확인됐습니다.
