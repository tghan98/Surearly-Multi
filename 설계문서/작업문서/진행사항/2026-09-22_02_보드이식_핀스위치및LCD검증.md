# 2026-09-22_02_보드이식_핀스위치및LCD검증

## 한 줄 요약

> 디버거 레지스터로 v1.1 보드의 LED 핀과 스틱 스위치를 확인하고, 광학 판정을 우회한 LCD 시퀀스가 정상 동작하는 것을 확인했습니다.

## 1. 뭘 하려던 거였나 (배경)

이번 단계의 목적은 광학 측정값을 검증하는 것이 아니라, 보드에 연결된 기본 입출력과 LCD 경로를 먼저 확인하는 것이었습니다.

광학용 LED는 케이스 안쪽을 향하고 있어 육안으로 점등 여부를 판단하기 어렵습니다. 따라서 디버거의 GPIOB 레지스터를 사용해 MCU가 실행 중인지, 핀 방향과 출력 상태가 맞는지, 스틱 스위치 입력이 변하는지를 확인했습니다.

## 2. 뭘 했나

### 2.1 디버거 레지스터로 LED 핀 검증

IAR 디버거에서 `PB_DDR`, `PB_CR1`, `PB_CR2`, `PB_ODR`, `PB_IDR`를 확인했습니다. PB4와 PB3은 출력·Push-Pull·Fast 설정이었고, 스틱을 뺀 상태에서 PB4는 Low, PB3은 High였습니다.

검증 방법은 `User_Main_Init()`의 `DM_HW_Drv_GPIO_Init()` 직후에 임시 코드를 삽입하는 방식이었습니다. LED1(PB4)을 고정 점등하고 PB1 입력 상태를 LED2(PB3)에 반영하는 `while` 루프에서 IAR 디버거를 중단한 뒤 Registers 창의 Port B 값을 읽었습니다. 옵션 바이트로 IWDG가 켜져 있을 가능성에 대비해 루프 안에서 `IWDG_ReloadCounter()`를 호출했으며, 검증 후 임시 코드는 제거했습니다.

실측 레지스터 값은 다음과 같습니다.

```text
PB_DDR = 0x1D
PB_CR1 = 0x1F
PB_CR2 = 0x18
스틱 뺌:   PB_ODR = 0x08, PB_IDR = 0x0A
스틱 꽂음: PB_ODR = 0x00, PB_IDR = 0xE0
```

### 2.2 스틱 감지 입력 검증

스틱을 뺀 상태에서 PB1 입력은 High였고, 스틱을 삽입하자 Low로 바뀌었습니다. 동시에 PB3 출력도 High에서 Low로 바뀌어 PB1이 실제 스틱 감지 스위치 입력임을 확인했습니다.

### 2.3 LCD 시퀀스 검증

광학 측정이 LCD 테스트를 막지 않도록 `_DEBUG_LCD_SEQ_ONLY`를 1로 설정하고, IDLE에서 기계식 스틱 감지로 깨어난 뒤 광학 스틱 판정을 건너뛰고 `STICK_INSERT` LCD 시퀀스로 전이하도록 변경했습니다.

스틱을 삽입한 뒤 LCD가 깜빡이고 아이콘을 순서대로 표시한 후 빈 화면으로 돌아오는 동작을 확인했습니다. 이는 LCD COM/SEG 핀, TIM4 인터럽트, LCD 위상 반전 갱신 경로가 동작한다는 뜻입니다.

### 빌드 결과

현재 확인된 IAR 맵 파일의 메모리 사용량은 다음과 같습니다.

```text
readonly code memory    : 4,338 bytes
readonly data memory    : 265 bytes
readwrite data memory   : 375 bytes
```

이 값은 `_DEBUG_LCD_SEQ_ONLY=1` 빌드 결과입니다. 광학 시퀀스 호출 경로가 제외된 디버그 빌드이므로 최종 펌웨어 크기로 사용하지 않습니다. 참고로 `_DEBUG_LCD_SEQ_ONLY=0` 첫 빌드의 값은 `6,780 / 284 / 390`이었으며, 전체 시퀀스 복구 후 최종 크기를 다시 측정해야 합니다.

빌드 경고 2건은 디버그 플래그로 광학 경로가 제외된 결과입니다.

```text
Warning[Pe550]: variable "gs_bTestCompleteCount" was set but never used
				USER/App/DM_Main_Sq_App.c 24

Warning[Pe177]: function "DM_App_Main_Sq_Sleep_And_CheckStick_250ms"
				was declared but never referenced
				USER/App/DM_Main_Sq_App.c 133
```

`_DEBUG_LCD_SEQ_ONLY=0`으로 전체 시퀀스를 복구한 뒤 두 경고가 사라지는지 확인합니다.

## 4. 걸린 것 / 남은 것

- `_DEBUG_LCD_SEQ_ONLY`는 3단계 측정 기간 동안 1로 유지합니다. 측정은 전체 시퀀스가 아니라 별도 진단 루틴과 디버거 Watch로 수행합니다. 0으로 되돌리는 시점은 PWM 잔재 제거와 2점 보간 구현이 끝난 뒤, 전체 시퀀스 검증 직전입니다.
- `DELAY_US_CAL`은 실제 on-time을 측정해 보정해야 합니다.
- `ADC_READ_TIME_US`는 16사이클 ADC의 실제 변환시간을 재측정해 갱신해야 합니다.
- ADC 변환 완료 플래그가 `ADC_GetConversionValue()` 호출로 자동 정리되는지는 아직 확인하지 않았습니다. 20개 샘플이 모두 같은 값이면 EOC 처리와 채널 선택을 우선 확인합니다.
- 3단계 착수 순서는 ADC EOC 처리 확인, `DELAY_US_CAL` 보정, ADC 변환시간 측정 및 `ADC_READ_TIME_US` 갱신, on-time 스윕 순서로 진행합니다.
- 현재 LED는 케이스 조립 상태에서 육안 확인이 어려우므로 GPIO 레지스터 또는 PTR ADC 값으로 판단해야 합니다.

## 5. 오늘의 교훈

육안으로 LED를 확인하려다 미점등으로 오판해 MCU·클럭·다운로드까지 의심했습니다. 실제로는 PB4가 처음부터 Low였고, 케이스 안이라 보이지 않았을 뿐입니다. 이 보드는 육안 확인이 어려우므로 앞으로 LED 점등 여부는 GPIO 레지스터 또는 PTR ADC 값으로 판단합니다.

## 6. 저장소 정리 (부수 작업)

줄바꿈 방식(CRLF/LF)이 도구마다 달라 96개 파일이 내용 변경 없이 수정 상태로 잡히는 문제가 있었습니다. 루트에 `.gitattributes`를 추가해 저장소는 LF, 작업 트리는 CRLF로 고정하고, `git add --renormalize`로 기존 파일을 일괄 정리했습니다. 커밋 `04e0894`가 그 전환 지점이며 소스 기능 변경은 없습니다.

IAR이 자동 생성하는 `OVULATION_MULTI_New.dep`는 `.gitignore`에 추가하고 `git rm --cached`로 추적 해제했습니다.
