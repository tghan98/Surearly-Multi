# 정상 기기 5·12번의 광량 저하

- 날짜: 2026-10-21
- 브랜치: `feature/stage10-wake-fail-record`
- 상태: 🔵 원인 미확정 — 하드웨어로 판단하고 범위 밖으로 둠

> **한 줄** — 정상으로 분류했던 5·12번의 광학 측정값이 하루 사이 **20~25%** 떨어졌다.
> 쓰는 동안에도 계속 떨어진다. **전지를 바꿔도, 펌웨어를 되돌려도 같다.**

## 지운 가설

### ① 스틱 불량 — 기각

12번에서 스틱을 새것으로 바꿔 꽂았더니 **오히려 더 떨어졌다** (2,975 → 2,674).

### ② 전지 — 반만 맞다

12번 전지 전압은 **2.72V**. LDO 가 2.5V 이상을 잡아주므로 이 전압 자체는 문제가 아니다.

11번 전지로 바꿔 끼우자 초기값이 2,771 → 3,342 로 **24% 회복**했다.
그러나 **완주는 여전히 실패**했고, 배율이 **45**까지 올라갔다.

> 배율이 45 라는 것은 그 시점 측정값이 약 2,670 이었다는 뜻이다.
> 초기 측정 때는 3,342 였다. **측정하는 동안에도 계속 떨어지고 있다.**

### ③ 새 펌웨어(10단계 ③) — 기각

같은 기기(5번)에서 펌웨어만 바꿔 비교했다. `git checkout 4239b0a -- USER/` 로
`USER/` 만 직전 커밋으로 되돌려 빌드했다.

| | 초기값 C |
|---|---|
| 오늘 펌웨어 15:18 | 2,945 |
| **어제 펌웨어 15:34** | **2,765** |

어제 펌웨어가 오히려 더 낮다. **펌웨어와 무관하다.**

## 공통점

- **네 채널이 같이 떨어진다.** 한 채널만 나쁜 것이 아니다
- **쓰는 동안에도 떨어진다.** 12번은 5분에 10%, 5번은 16분에 6%
- **두 기기가 같은 모양이다.** 개별 불량으로 보기엔 공통점이 크다
- 1,500~3,900 범위 안이라 **초기 범위 검사에는 안 걸린다.**
  검사 중 결과값이 430~636 으로 폭락해서 `ERROR_STICK_FAIL` 로 끝난다

> 배율도 32~33 에서 **37~45** 로 올라가 있다. 배율이 올라간다는 것은
> 같은 목표(1,200)에 맞추기 위해 더 크게 곱해야 한다는 뜻이고, 곧 빛이 덜 들어온다는 뜻이다.

## 다음에 볼 곳 (하드웨어)

전지와 펌웨어를 지웠으므로 남은 것은 기기 쪽이다.

| 후보 | 어떻게 |
|---|---|
| **LDO 출력** | LED 가 켜진 동안의 출력 전압. 다만 LED 점등이 20ms 라 멀티미터로는 어렵다 |
| **PTR 전원** | 기준서 8장 「남은 확인」에 "PTR 이 상시 VCC 에 물려 있어 대기전류 증가" 항목이 있다 |
| 전원 커패시터 | LED 전류를 받쳐주지 못함 |
| 광학부 오염 | 센서·LED 창 이물 |

**상급자 지시(10-20)로 하드웨어 문제는 불량 처리하고 범위 밖이다.**
여기까지 기록만 남기고 더 파지 않는다.

## 곁다리로 확인된 것

### Wake Fail 칸이 처음으로 쓰였다

12번과 5번 모두 `Wake Fail = 0 / 0` 이었다.

| 보이는 값 | 뜻 |
|---|---|
| 65535 / 0 | 아직 기록 없음 |
| **0 / 0** | **0 이 한 번 이상 기록됨** |

0 은 ADC timeout 또는 실제 입력 0 이다. 구별되지 않는다(설계 시 알고 있던 한계).
어느 쪽이든 **깨어나긴 했고 그때 CH3 가 바닥이었다**는 뜻이다.

> 같은 시간대 초기 측정은 2,600~3,300 이 나왔다. 같은 채널인데 한쪽은 0, 한쪽은 3,000대다.
> 전원이 흔들리는 그림과 맞는다.

### PC UI 가 신·구 펌웨어를 모두 읽게 했다

어제 펌웨어로 되돌려 재려다 막혔다. 기기는 269 바이트를 보내는데 UI 가 273 을 기다려
`수신 중... 269 / 273` 에서 멈췄다.

UI 를 바꿔 끼우는 대신 **둘 다 받도록** 고쳤다. 269 까지 받고 300ms 동안 더 오지 않으면
구 펌웨어로 보고 거기서 끝낸다. 그때 Wake Fail 은 `-` 로 둔다.

> 앞으로도 구 펌웨어가 들어간 기기를 만난다(13대 중 아직 안 구운 것, 현장 회수품).
> 그때마다 UI 를 바꿔 끼우면 잊어버리고 "GUI 가 고장났나" 로 착각한다. 실제로 한 번 그랬다.

## 오늘의 교훈

**같은 기기로 비교해야 한다.**

펌웨어 탓인지 가리려 할 때 "1번 기기는 아직 안 구웠으니 그걸로 보자"고 했다가
**다른 기기는 비교가 안 된다**는 지적을 받았다. 같은 기기에서 펌웨어만 바꿔야 한다.

비교 기준선 불일치를 또 한 것이고, 이번 주만 세 번째다.
(주간보고 마진 285, 10번 기기 결과 밴드값 1,452, 그리고 이번)

> **다음부터** — "A와 B를 비교한다"고 할 때, **A와 B 사이에 바뀐 것이 하나뿐인지**를
> 먼저 센다. 둘 이상이면 비교가 아니다.
