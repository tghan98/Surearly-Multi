## 1. 확정된 하드웨어

### 1-1. 대상 보드

- 기판 실크 **2025.05**, 라벨 **250704**
- MCU **STM8L151F3** (TSSOP20) — 칩 마킹 `8L151F3P6` 확인
- 배선은 **v1.1 계열**(2022 회로도)이나, 광학부 부품은 **2023년 개선판 사양**

### 1-2. 핀맵 (실물 도통 측정)

**회로도 r1574와 한 군데 다르다** — PB2가 미사용(X)으로 그려져 있으나 실제로는 LCD COM에 연결됨.
구펌웨어(`MFx_v2.1.1_alpha.2`)의 `LCDCOM_PIN = GPIO_Pin_2`가 맞았다.

| 신호 | MCU 핀 | 근거 | 현재 코드(v2.1) |
|---|---|---|---|
| nLED1 | **PB4** (14) | 실측 0.13Ω | PC0 |
| nLED2 | **PB3** (13) | 실측 0.14Ω | PC1 |
| LCD_COM0 | **PB2** (12) | 실측 1kΩ | PB4 |
| LCD_SEG3 | **PB0** (10) | 실측 1kΩ | PB0 (동일) |
| LCD_SEG0 / SEG1 / SEG2 | PC5 / PC6 / PD0 | 회로도·구펌웨어 일치 | 동일 |
| PTR1 / PTR2 / PTR3 (ADC) | PB5 / PB6 / PB7 | 회로도·구펌웨어 일치 | 동일 |
| SW_STRIP | PB1 (11) | 실측 확인(2026-09-22, 디버거 GPIOB IDR) | 동일 |
| USART TX / RX | PA2 / PA3 | 동일 | 동일 |
| PC0, PC1 | **미사용** | 실측 OL | nLED1/nLED2 |

**측정 기준** — LCD 신호선에 1k 직렬저항(R7~R10)이 있어 연결된 세그먼트·COM은 0Ω이 아니라 **1kΩ 근처**로 읽힌다. LED 캐소드(L1/L2 패드)는 직결이라 0Ω. 수백 kΩ 이상은 전부 미연결.

**검증 결과(2026-09-22)** — 디버거 GPIOB 레지스터에서 PB4/PB3 출력과 PB1 풀업 입력을 확인했다. 스틱을 삽입하면 PB1이 High에서 Low로 바뀌고 PB3 출력도 High에서 Low로 바뀌었다. LED는 케이스 조립 상태에서 육안 확인이 어려우므로 GPIO 레지스터 또는 PTR ADC 값으로 판단한다.

### 1-3. 광학부 실장값 (사진 판독)

| 부품 | 값 | 근거 |
|---|---|---|
| R13 (LED 직렬) | **510Ω** | 칩 마킹 `511` |
| R1~R3 (PTR 부하) | **100kΩ 1%** | 칩 마킹 `01D` (EIA-96) |
| C12~C14 (PTR 필터) | **47nF** (추정) | 재고 `473K` · BOM r1897 |
| R4, R5 | 100kΩ 5% | 칩 마킹 `104` |

→ **PTR 시상수 τ = 100k × 47nF ≈ 4.7ms**

2023년 개선판과 같은 부품 구성이다. 구펌웨어가 이 조합에서 돌았으므로 그 설정값을 출발점으로 신뢰할 수 있다.

| 구펌웨어 기준값 | 값 |
|---|---|
| `_nTAGET_LIGHT` | 3000 |
| `_nBAND_LIGHT_MAX` / `MIN` | 3800 / 400 |
| 실기 LED on-time | LED4 759us, LED5 843us |
| T / C 임계값 | 1040 / 1050 (현재 코드와 동일) |

단, 구펌웨어는 ADC 단일 변환값을 쓰고 신규 코드는 **20샘플 중 중앙 14개의 합계**를 쓴다. 스케일이 다르므로 숫자를 그대로 옮기지 말 것.

### 1-4. 없는 하드웨어

- **LED_PWM 핀 없음** — LED 애노드가 R13(510Ω)으로 VCC 직결. PB2는 COM으로 점유. 밝기의 하드웨어 제어 수단이 없다
- **PTR_PW 없음** — 포토트랜지스터 컬렉터가 VCC 직결, 전원 게이팅 불가

## 2. 핵심 설계 변경 — 밝기 제어에서 점등시간 제어로

현재 코드는 `DM_App_Optic_Measure(ch, wPWM)`에서 TIM2_CH2 PWM 듀티(0~399)로 밝기를 조절하고,
`DM_App_Optic_TuneTargetADC()`가 P제어로 듀티를 찾는다. **이 축이 이 보드에는 없다.**

대신 구펌웨어 방식을 되살린다 — **LED를 켠 뒤 ADC를 읽기까지의 대기시간(on-time)** 조절.
PTR 출력이 R·C를 충전하는 과도구간(τ≈4.7ms)에서 샘플링 시점을 옮겨 레벨을 만든다.
구펌웨어 실측 on-time 759~843us는 0.16~0.18τ 지점, 상승 구간에서 거의 선형인 영역이다.

```c
x2 = 500; x1 = 100;                       // 두 지점의 on-time
LED_OnTime[1] = x2;  C_Scan(...);  y2 = wEmpty_C;
LED_OnTime[1] = x1;  C_Scan(...);  y1 = wEmpty_C;
Cal_Line_Coef(x1, y1, x2, y2, &C_a, &C_b);           // 직선 피팅
wLED_OnTime[1] = Cal_LED_Time(C_a, C_b, _nTAGET_LIGHT); // 목표 광량 역산
```

2점 선형 보간이라 현재의 5회 P제어보다 측정 횟수도 적다.

### 2-1. 전제 조건 — ADC 읽기를 빠르게 해야 한다

**이 변경 없이는 on-time 제어가 성립하지 않는다.**

현재 `DM_App_Optic_Measure()`는 ADC를 20회 연속으로 읽는데 한 번에 220us, 합계 약 4.4ms가 걸린다.
그 4.4ms 동안에도 LED가 켜져 있어 PTR 노드는 계속 충전되므로, on-time(약 800us)은 버스트의
**시작점만** 정할 뿐 실제 적분 구간을 지배하지 못한다.

τ≈4.7ms 기준으로 on-time을 0~3ms로 움직여도 읽히는 값은 **약 1.8배**밖에 변하지 않는다.
스틱 편차 보정에는 턱없이 부족하다.

**원인 1 — 샘플링 시간 과다 설정**

`DM_HW_Drv_ADC_Init()`이 `ADC_SamplingTime_384Cycles`를 쓴다. `Work_20260423.md`에 그 이유가
"높은 RC 시정수(100K/22nF)를 고려하여"라고 적혀 있으나 **이는 오해다.** ADC 샘플/홀드가 전하를
받아오는 상대는 100k 저항이 아니라 노드에 병렬로 붙은 수십 nF 커패시터이며, 내부 S/H 용량(수십 pF)
대비 1000배 이상 크므로 짧은 샘플링으로 충분하다.

**원인 2 — wfi/EOC 인터럽트 오버헤드**

`Work_20260804.md`의 계산값 `(12+384)/2MHz = 198us`와 코드의 실측값 `ADC_READ_TIME_US 220`의
**차이 22us가 wfi 진입·EOC 인터럽트 처리 오버헤드**다. 샘플링만 줄이면 변환은 8us가 되지만
이 22us가 그대로 남아 한 번에 30us, 20회 600us가 되어 on-time 800us와 비슷해진다. **효과가 없다.**

**조치 — 둘을 함께 바꾼다**

| 항목 | 현재 | 변경 후 |
|---|---|---|
| 샘플링 시간 | 384 사이클 (192us) | **16 사이클 (8us)** |
| 변환 대기 | `wfi()` + EOC 인터럽트 | **EOC 플래그 폴링** |
| 1회 읽기 | 220us | 약 14us |
| 20회 버스트 | 4.4ms | **약 0.28ms** |
| on-time 0~3ms 시 값 변화 폭 | 약 1.8배 | **약 28배** |

**짧게 읽어도 되는 근거**

ADC 샘플링 시간은 내부 S/H 커패시터(십수 pF)를 바깥에서 채우는 데 걸리는 시간이다. 얼마나 걸리는지는
**바깥이 전하를 얼마나 빨리 내주느냐**로 정해진다.

원 설정은 바깥을 100k 저항으로 보고 잡은 값이다. 100k로 16pF를 채우면 시상수 1.6us, 12비트 정착에
약 14us가 필요하므로 여유를 크게 둬 192us가 됐다.

그러나 노드에는 **C12~C14(수십 nF)가 병렬로 붙어 있다.** S/H가 전하를 요구하면 100k를 거치는 것이
아니라 이 커패시터에서 즉시 공급된다. S/H 용량 대비 약 3000배이므로 1회 샘플링으로 빠져나가는 전하는
노드 전압의 0.03% 수준이다. 따라서 짧은 샘플링으로 충분하다.

**전제와 한계**

- 이 근거는 **커패시터가 붙어 있다는 전제** 위에 성립한다. 보드 사진에서 C12~C14 실장을 확인했다
- 커패시터가 없다면 100k만으로 8us는 부족하다 (12비트에 약 14us 필요). 최초 계획서에
  "커패시터가 없어도 충분하다"고 적었던 것은 잘못이며 이 항목으로 정정한다
- 16 사이클을 고른 것은 최소값(4 사이클) 대비 배선 저항 등 예상 못 한 요인에 대한 **여유 마진**이다

**검증** — 계산에 의존하지 말고 2단계에서 **동일 조건을 384 사이클과 16 사이클로 각각 읽어 값이
일치하는지** 확인한다. 불일치하면 64 사이클(32us)까지 올리되, 20회 버스트가 760us가 되어 on-time
800us와 비슷해지므로 그때는 샘플 수 축소를 함께 검토한다.

**부수 효과 — 20샘플 필터를 그대로 유지할 수 있다.** 버스트를 1~3회로 줄이는 대안은 노이즈 내성을
포기해야 하지만, 이 방식은 정렬·중앙 14개 합계 구조를 손대지 않는다.

## 4. 진행 단계

### 1단계 — 핀 재배치 + 기본 동작

목표: 보드가 켜지고 LED가 점등되고 LCD가 표시되는 것까지.

- 3-1 ~ 3-4의 핀·GPIO·TIM2 제거·PTR 전원 제거
- `DM_App_Optic_Measure()`는 고정 on-time(예: 800us)으로 동작만
- 튜닝 로직은 건드리지 않고 임시로 bypass

검증: LED1/LED2 각각 점등, LCD 아이콘 4개 점등/소등, 스틱 삽입 시 wake-up.

**주의** — 1단계 전에 현재 펌웨어를 이 보드에 절대 쓰지 말 것. PB3(PTR_PW)·PB4(LCD_COM) 구동이 LED를 상시 점등시키거나 100Hz로 깜빡이게 한다.

### 2단계 — on-time 스윕으로 실측 데이터 확보

- on-time을 스윕하며 4채널 ADC 값을 USART로 출력하는 **임시 테스트 빌드**
- 범위: **50us ~ 5ms** (τ≈4.7ms이므로 15ms 이상에서는 포화 예상). 로그 간격 권장
- 블랭크 스틱 삽입 상태에서 측정
- 확인할 것:
  - 상승 곡선이 τ≈4.7ms와 맞는지 → C12~14가 실제 47nF인지 간접 검증
  - 선형 구간 → `X1`/`X2` 결정
  - 구펌웨어 대비 스케일 환산 → `_nTAGET_LIGHT` 결정
  - **384 사이클과 16 사이클의 읽기 값이 일치하는지** (2-1 변경 검증, 최우선)
  - 짧아진 버스트(0.28ms) 동안의 상승분이 무시 가능한지
- 기기 여러 대로 반복해 개체 편차 확인 → `OPTIC_INITIAL_MIN/MAX` 범위 설정

### 3단계 — 튜닝 로직 교체 및 파라미터 확정

- 2점 선형 보간 튜닝 구현

- 스틱 제거 판정 임계값 재설정

### 4단계 — 전체 시퀀스 검증

- 실제 스틱으로 양성/음성 검사
- **`ADC_READ_TIME_US` 재도출** — ADC 읽기가 220us에서 약 14us로 바뀌므로 이 상수를 반드시 갱신한다.
  이 값은 `Work_20260804.md`·`Weekly_Report_20260806.md`의 "5분 대기 5:06" 보정 이력의 핵심 인자다.
  220을 그대로 두면 실제보다 많은 시간을 계상해 **5분 대기가 짧게 끝난다.**
- 5분 대기 타이밍 재측정 (on-time 대기와 ADC 시간이 tick에 정확히 반영되는지)
- 측정이 빨라지면 대기 루프 반복 횟수가 늘어난다. 과거 5:35로 재악화된 원인이 같은 구조였으므로
  TIM4 ARR(149) 재보정이 필요한지 확인한다
- EEPROM 덤프로 저장값 검증
- 코드 사이즈 확인 (현재 Flash 91%, 여유 약 770B. TIM2 제거로 다소 확보될 것)

## 5. 남은 확인 사항

- **C12~C14 실측** — 무표기 부품이라 2단계 곡선으로 간접 확인.
  다만 **1nF는 배제할 수 있다.** 1nF이면 τ=0.1ms이므로 구펌웨어의 on-time 759~843us는 8τ로
  완전 포화돼 레벨 조절 자체가 불가능하다. 실제로 조절이 됐으므로 22nF(τ 2.2ms) 또는
  47nF(τ 4.7ms)만 후보다. 22nF는 원 개발자 기록(`Work_20260423.md`)·v2.1 회로도,
  47nF는 BOM r1897·재고 근거이며, 우리 보드는 BOM r1897 사양이므로 47nF가 유력하다
- **측정 중 인터럽트 차단은 불필요** — TIM4는 `DM_HW_Drv_SystemSleep_10ms()` 안에서만 enable되고
  빠져나오며 disable되므로, on-time 대기와 ADC 버스트 동안에는 꺼져 있다. LCD 갱신 인터럽트가
  끼어들 일이 없다. USART RX만 남는데 진단 시에만 발생한다
- **LCD SEG0/1/2** — 회로도·구펌웨어가 일치하므로 미측정. 1단계에서 아이콘이 엉뚱하게 켜지면 확인
- **Halt 소비전류** — PTR이 상시 VCC에 물려 있어 대기전류 증가 가능. CR1632 수명 영향 확인 필요
- **문서 불일치** — 회로도 r1574의 PB2 표기, R13 값이 실물과 다름. 인수인계 폴더의 핀맵 문서 3종도 서로 모순되며 실물과 불일치
