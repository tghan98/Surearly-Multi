## 1. `EEPROM_UART.md` 문서 작성

### 1-1. 배경

EEPROM에 저장되는 데이터 구조와, 이를 읽어 USART로 PC에 전송하는 프로토콜을 바탕으로 PC용 GUI(수신/파싱 프로그램)를 만들기 위한 참고 문서가 필요하다는 요청.

### 1-2. 내용

`USER/App/DM_Rom_Handl_App.c/.h`, `USER/Drive/DM_HW_Drv.c`, `USER/User_Main.c`, `USER/App/DM_Main_Sq_App.c`, `USER/Parameter_define.h`를 코드 기준으로 조사해 프로젝트 루트에 `EEPROM_UART.md` 신규 작성:

- **EEPROM 구조**: STM8L15x 내장 Data EEPROM(0x1000 시작, 오프셋 0~243/244바이트 사용) 맵 — InsertCount(1B)/TestCompleteCount(1B)/ErrorStep(1B)/ErrorCode(1B)/Stick PTR 초기 캘리브레이션(8 word)/최근 7회 결과 레코드(각 32바이트 순환 버퍼, `bIndex % 7`). 각 결과 레코드 내부 word 구성(PWM 4 + EmptyBand 4 + ResultBand 4 + 계산결과 3 + Dummy 1)까지 전부 정리.
- **USART 프로토콜**: USART1, 9600-8N1, PA2(TX)/PA3(RX). 헤더/길이/CRC 없는 단순 커맨드 프로토콜 — `'M'/'m'`+CR/LF(EEPROM 전체 덤프), `'R'/'r'`+CR/LF(TestCompleteCount 리셋). 덤프 응답은 총 269바이트 고정길이 바이너리(버전/LOT 문자열 헤더 21바이트 + 상태 4 word + 캘리브레이션 8 word + 결과 7×16 word), 모든 다중바이트 값은 big-endian.
- GUI 파서가 그대로 쓸 수 있도록 **바이트 오프셋 테이블**(0~268, 필드별 크기/타입)을 별도 절로 정리.

## 2. USART 수신 인터럽트 동작 방식 확인 (코드 변경 없음, Q&A)

- `DM_HW_Drv_USART_Init()`에서 `USART_ITConfig(USART1, USART_IT_RXNE, ENABLE)`로 RXNE 인터럽트가 켜져 있음을 확인.
- RXNE는 STM8 하드웨어상 **한 번 켜두면 계속 유지되는 활성화 비트**이며, 매 인터럽트마다 재활성화가 필요하지 않음. 플래그 자체는 `USART_ReceiveData8()`로 데이터 레지스터를 읽는 순간 하드웨어가 자동으로 클리어함(`USER/User_Main.c`의 `USART1_RX_TIM5_CC_IRQHandler` 확인) — 따라서 인터럽트 핸들러에서 별도로 재활성화(`USART_ITConfig` 재호출)할 필요 없음.

## 3. C-Line Fail 시 T/C Intensity 값이 EEPROM에 저장되지 않는 버그 수정

### 3-1. 증상 (사용자 실기 확인)

C-Line Fail(`ERROR_C_LINE_FAIL`) 발생 시, 해당 테스트의 T Intensity/C Intensity 값이 EEPROM에 저장되지 않고 이전 값이 남아있음.

### 3-2. 원인

`DM_App_Main_Sq_Result_Scan_Step_Handler()`(`DM_Main_Sq_App.c`)에서 `wResult_C`가 C-Line 임계값 미달이면 곧바로 `return`하는데, 이 `return`이 `gs_awResult[RES_T_INTENSITY]`/`gs_awResult[RES_C_INTENSITY]`를 채우는 코드보다 **앞**에 있었음. 에러 처리 루틴(`Error_Wait_Step_Handler` → `Save_Result_To_Rom`)이 이 `gs_awResult[]`를 그대로 EEPROM에 패킹하므로, C-Line Fail 시에는 이번 테스트의 계산값이 아니라 이전 테스트에서 마지막으로 저장된(또는 최초라면 0인) stale 값이 그대로 저장되고 있었음. (raw band ADC값인 `gs_awResultBand_LowData`는 C-Line 체크보다 먼저 갱신되므로 정상 저장됨 — 계산된 Intensity/판정값만 문제였음.)

### 3-3. 수정

`wResult_T`/`wResult_C` 계산 직후, C-Line 유효성 체크(및 그로 인한 `return`)보다 먼저 `gs_awResult[RES_T_INTENSITY]`/`gs_awResult[RES_C_INTENSITY]`를 저장하도록 순서 변경. `RES_YES_NO`는 기존과 동일하게 T-Line 판정 성공 경로에서만 저장(C-Line Fail 시엔 YES/NO 판정 자체가 무의미하므로 그대로 둠).

## 4. Wake-up 직후(Step 1) 이전 사이클 잔존 데이터 리셋

### 4-1. 배경

Wake up 후 첫 스텝(`DM_App_Main_Sq_Stick_Insert_Step_Handler`, MAIN_SQ_STICK_INSERT)에서 이번 사이클이 이 스텝 내의 에러 경로(사용횟수 초과, 스틱 제거, 광학 튜닝 실패 등)로 중간에 실패해 EEPROM에 저장될 경우, PWM/Empty Band/Result Band/Intensity 값이 이전 테스트의 값을 그대로 유지한 채 저장되고 있다는 문제 제기.

### 4-2. 수정 내용

- `DM_Optic_Handle_App.c/.h`: `DM_App_Optic_ResetPWM(void)` 함수 신규 추가 — 파일 static인 `gs_wOptic_PWM[OPTIC_CH_MAX]`를 4채널 모두 0으로 리셋 (외부에서 직접 접근 불가하므로 접근자 함수로 노출).
- `DM_Main_Sq_App.c`: `Stick_Insert_Step_Handler()`(`#else` 분기) 맨 앞, 즉 이 스텝의 모든 에러 return보다 먼저 다음을 실행하도록 추가:
  - `DM_App_Optic_ResetPWM()` 호출 (PWM CH1~4 → 0)
  - `gs_awEmptyBand_LowData[BAND_MAX]`(ET/EBT/EBC/EC), `gs_awResultBand_LowData[BAND_MAX]`(RT/RBT/RBC/RC) 전부 0
  - `gs_awResult[RES_MAX]`(T Intensity/C Intensity/Yes-No) 전부 0
- PWM은 기본값(199)이 아니라 요청대로 **0**으로 리셋 — "이번 사이클에서 아직 측정/튜닝되지 않았음"을 이전 테스트의 실측값과 명확히 구분하기 위함.
