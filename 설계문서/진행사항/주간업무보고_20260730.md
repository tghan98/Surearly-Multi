## 2. 상세 내용

### 2-1. PCB Pin Map 변경 반영 (07-28)
- 06/16 지적된 **PC1(PTR_PW) True Open-Drain 문제**를 핀 재배치로 해결: LED1/2 → PC0/PC1(True OD), PTR_PW → PB3, LCD_COM0 → PB4(Push-Pull).
- `main.h` 핀 정의, `DM_HW_Drv.c` GPIO 모드/LED 제어 극성/Sleep 전처리 로직을 새 매핑에 맞게 수정.
- LCD_COM0가 Push-Pull로 이동하면서 기존 AC 구동(위상반전) 로직이 비로소 정상 동작할 것으로 기대(실물 확인 필요 항목으로 남김).
- IAR 컴파일 성공 확인.

### 2-2. 광학 튜닝 실측 검증 (07-28~29)
- TIM2 PWM 극성이 06/15 "역조립 대응" 값 그대로 남아있어 PWM↑ 시 ADC가 폭락하는 문제 발견 → 극성 복원(`TIM2_OCPolarity_High`)으로 해결, PWM199→399 시 ADC 정상 증가 확인.
- 튜닝 목표값 `_nTAGET_LIGHT`을 실측 범위에 맞춰 800→2000→(제조 편차 여유 확보를 위해)1000으로 재조정, `OPTIC_TUNE_TOLERANCE` 30→15로 강화.

### 2-3. "Count 변수 스킵" 버그 — 원인 정정 (07-28 오판 → 07-29 확정)
- 07-28: `MeasureEmptyPTR()` 등에서 특정 채널만 0이 나오는 현상을, "컴파일러가 루프를 스킵한다"고 판단해 `bCh`를 `volatile`로 우회 처리.
- 07-29: 파라미터 재조정 및 튜닝 로직 재활성화 후 동일 증상 재발. 사용자 실측(전역 변수로 바꾸면 정상, 지역 변수면 오동작)으로 **실제 원인은 IAR STM8 "small" 코드 모델이 함수 호출을 넘나드는 지역변수를 공유 가상 레지스터에 배치하며 값이 덮어써지는 문제**로 확정(루프 스킵이 아니었음).
- 함수 호출 경계를 넘어 값이 유지돼야 하는 모든 Count/인덱스 지역변수를 `volatile`→`static`으로 전면 전환(`DM_Optic_Handle_App.c`, `DM_Main_Sq_App.c`, `DM_HW_Drv.c`, `DM_LCD_Stick_Check_App.c`, `DM_Rom_Handl_App.c`, `DM_Utill.c`).
- 실물 보드 재측정으로 4채널 모두 target±tolerance 내 정상 측정 확인 → **해결 확정**. (이 IAR STM8 한정 이슈이며, 툴체인 변경 시 재검토 필요)

### 2-4. BOOK 아이콘 이상 동작 — 하드웨어 결함 오판 후 실제 원인 규명 (07-29)
- PC5(BOOK, LCD_SEG0)만 희미하게 켜지는 현상 발견. GPIO 모드, 크리스탈 부하, 타이밍, 소프트웨어 로직 순으로 배제하며 한때 "하드웨어 결함"으로 잠정 결론.
- `USART_Init()` 직후 BOOK이 High로 전환되는 것을 단서로, PC5가 **USART1_TX Remap 대체 핀**이라는 사실 확인.
- 근본 원인: `DM_HW_Drv_USART_Init()`이 PA2/PA3를 쓰려 했으나 `SYSCFG_REMAPPinConfig()`를 호출한 적이 없어 remap이 적용되지 않고 있었음 → **소프트웨어 설정 누락**이었지 하드웨어 결함이 아니었음.
- `SYSCFG_REMAPPinConfig(REMAP_Pin_USART1TxRxPortA, ENABLE)` 추가로 해결 확인. 조사용 임시 디버그 코드는 모두 정리 완료.

### 2-5. 코드 사이즈 절감 (07-29)
- UART CSV 전송 → Raw uint16_t 전송 전환, LCD 애니메이션 테이블화, 에러 처리 보일러플레이트 함수화(11곳) 진행.
- 3단계 누적으로 6,432B(78.5%)까지 절감(시작 7,258B 대비 826B, 10.1%↓).
- 이후 지역변수 버그 대응을 위해 최적화 레벨을 Medium→Low로 변경하면서 사이즈가 크게 증가(+914B), static 전환에 따른 rw data 증가(+30B)까지 반영한 **최종 수치: 7,109B (86.8%)**.

### 2-6. 기타
- LCD 시퀀스만 육안 확인할 수 있는 테스트 모드(`_DEBUG_LCD_SEQ_ONLY`, `_DEBUG_SEQ_STEP_DELAY`) 구현 — 전체 사이클 13분 → 약 32.5초로 단축.
