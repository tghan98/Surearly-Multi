## 1. LED 전류 계산 (PWM.txt 검토)

### 참조 파일
- `PWM.txt`
- 결과 파일: `LED_Current_Cal.md` (신규 생성)

### 하드웨어 구조

```
PWM_PIN(PB2) ─── R(51Ω) ──┬── LED1(LTW-C191KGKT) ── LED1_GPIO(PB4) ── GND
                            └── LED2(LTW-C191KGKT) ── LED2_GPIO(PB3) ── GND
```

- PWM_PIN(PB2): High측 소스 / LED_GPIO_PIN: Low측 싱크
- LED1, LED2가 51Ω 저항 1개를 공유하는 병렬 구조

### 전압 조건

| 항목 | 값 |
|------|----|
| VCC | 2.5V (LDO 출력) |
| GPIO VOH (저전류) | ≈ 2.4V |
| GPIO VOL (저전류) | ≈ 0.1V |
| 실효 구동전압 | **2.3V** |

### 전류 계산 결과

**공식:** `I_peak = (V_drive - Vf) / 51Ω`, `I_avg = I_peak × Duty Cycle`

| 조건 | Case A (Vf=2.0V) | Case B (Vf=2.4V) |
|------|-----------------|-----------------|
| PWM 99% (LED 1개) | **5.84mA** | **≈1.98mA** |
| PWM 10% (LED 1개) | **0.59mA** | **≈0.20mA** |
| PWM 99% (LED 2개 동시) | 각 **2.91mA** | 각 **≈0.99mA** |
| PWM 10% (LED 2개 동시) | 각 **0.29mA** | 각 **≈0.10mA** |

> LTW-C191KGKT 데이터시트에서 동작 전류 기준 Vf 값 확인 필요  
> VCC = 2.5V 조건에서 Vf < 2.3V 이어야 정상 점등 가능

## 2. DM_App_Optic_Measure() 함수 수정

### 참조 파일
- `USER/App/DM_Optic_Handle_App.c`

### 버그 발견

```c
/* 8. Return average */
//return (uint16_t)(dwSum / 6);   ← 평균 계산이 주석 처리됨
return (uint16_t)(dwSum);         ← 합계(×6 값)를 그대로 반환 중
```

- 함수 이름/주석은 평균 반환이라 명시되어 있으나 실제로는 **6배 큰 합계값** 반환
- ADC 값이 작아 합계로 계산하는 것이 의도임을 확인 → 합계 반환 유지

### 수정 이력

#### 수정 1: 10회 → 20회 측정, 중간 6개 → 16개 합산

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| 배열 크기 | `awSamples[10]` | `awSamples[20]` |
| 측정 루프 | `i < 10` | `i < 20` |
| 버블 정렬 범위 | `i < 9`, `j < 10` | `i < 19`, `j < 20` |
| 합산 범위 | `i <= 7` (6개) | `i <= 17` (16개) |
| 측정 총 시간 | 100ms | 200ms |

#### 수정 2: 최솟값/최댓값 제거 2개 → 3개, 합산 16개 → 14개

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| 제거 개수 | 최솟값 2개 / 최댓값 2개 | 최솟값 3개 / 최댓값 3개 |
| 합산 범위 | Index 2 ~ 17 (16개) | Index 3 ~ 16 (14개) |

```c
/* 7. Sum the middle 14 values (Index 3 to 16) */
for (i = 3; i <= 16; i++)
{
    dwSum += awSamples[i];
}
```

**uint16_t 오버플로우 여유:**  
`4095 × 14 = 57,330` (uint16_t 최대 65,535) → 여유 8,205 ✅

## 3. DM_App_Main_Sq_Stick_Insert_Step_Handler() 소요 시간 분석

### 참조 파일
- `USER/App/DM_Main_Sq_App.c`
- `USER/App/DM_LCD_Stick_Check_App.c`
- `USER/User_Main.c`

### 질문
> MCU 2MHz 동작 시, `DM_App_Main_Sq_Stick_Insert_Step_Handler()` 진입부터  
> `while (DM_App_LCD_Sq_Get_Step() != LCD_SQ_IDLE)` 탈출까지 소요 시간은?

### 분석 구조

```
t=0ms   함수 진입 + LCD_SQ_STICK_INSERT 시작 (TIM4 인터럽트로 병렬 구동)
   │
   ├─ ROM 읽기/쓰기                              ~10ms
   ├─ MeasureInitialStick: 4채널 × 2 PWM × 200ms  1,600ms
   ├─ TuneTargetADC: 4채널 × 평균 2회 × 200ms     1,600ms (800~4,000ms)
   ├─ MeasureEmptyPTR: 4채널 × 1회 × 200ms          800ms
   │                                            ──────────
   │  while 루프 도달                           ≈ 4,010ms
   │
   └─ while 루프 대기 (LCD 잔여 시간 ~990ms)
```

### LCD 애니메이션 총 길이 (~5,000ms)

| SubStep | 동작 | 시간 |
|---------|------|------|
| 0~4 | ALL ON/OFF 3회 반복 (blink) | 5 × 500ms = 2,500ms |
| 5→6 ~ 13→14 | DROP / YES / NO / BOOK / DROP 순차 점등 | 5 × 500ms = 2,500ms |
| 15 | END → LCD_SQ_IDLE | ~10ms |
| **합계** | | **≈ 5,000ms** |

> LCD 프로세스는 `TIM4_UPD_OVF_TRG_IRQHandler` (10ms 인터럽트)에서  
> `DM_App_LCD_Sq_Process()` 호출로 광학 측정과 **병렬** 진행

### 최종 소요 시간

| 구간 | 시간 |
|------|------|
| 광학 측정 (while 루프 도달까지) | ≈ 4,010ms |
| while 루프 대기 (LCD 잔여 시간) | ≈ 990ms |
| **while 루프 탈출까지 총 시간** | **≈ 5,000ms (약 5초)** |

- **병목:** LCD 애니메이션(5초)
- TuneTargetADC 최악(4,000ms)인 경우 광학 측정이 6,400ms → LCD 이미 완료 → while 즉시 탈출
- TuneTargetADC 최선(800ms)인 경우 광학 측정이 3,200ms → while 루프 약 1,800ms 대기
