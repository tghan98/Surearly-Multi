## 2. 펌웨어 (2026-08-04)

### 2-1. 측정시간 단축 및 타이밍 재보정 (핵심)
- `DM_App_Optic_Measure()`: 샘플마다 10ms씩 대기하던 구조(200ms)를 "LED ON 후 1회만 10ms 안정화 → 20샘플 연속 측정"으로 재구성 → **채널당 24ms (8배 단축)**.
- 부작용: 측정이 빨라지면서 5분 대기 루프의 ADC 호출수가 25,000회 → 95,000회로 급증, `Sample_Load_Wait`가 5:02 → 5:35로 재악화.
- 대응: 250ms 단위 스틱체크 헬퍼 신규 추가로 폴링 재구성 → ADC 호출수 약 18,000회로 복귀.
- 기존 TIM4 ARR(144) 보정값이 ADC 측정과 뒤섞인 "오염된" 기준이었음을 발견 → 순수 TIM4 재측정 후 ARR 149로 재보정, `ADC_READ_TIME_US` 200→220 갱신.
- 최종 실측: **5:06 (목표 대비 +6초, 약 2%)** — 추가 튜닝의 이론적 개선폭이 미미해 사용자가 잔여오차 수용, 튜닝 종료.

### 2-2. 신규 LED(LTST-C193KGKT-5A) 검토 및 Bin 지정 구매 결정
- 기존/신규 LED 데이터시트의 테스트 전류 기준(20mA vs 5mA)이 달라 raw 스펙 직접 비교가 무효함을 확인, 회로 실동작 전류(~1~2mA) 기준으로 재계산.
- "저항을 낮추면 Bin 편차가 준다"는 가설을 수식으로 검증해 **틀렸음을 확인**(저항값은 상대 편차 계산에서 약분되어 무관).
- **결정: VF Bin E2(1.7~1.9V) + IV Bin K(7.1~11.2mcd) 지정 구매** — 편차 최소화 및 밝기 균일성 확보.

### 2-3. 코드 사이즈 최적화 시도 → 실패, 전체 원복
- 중복 함수 통합 등 4개 항목 구현 후 실측한 결과 코드 사이즈가 오히려 소폭 증가(RO code +3, RO data +14, RW data +1).
- 원인: 작은 함수의 공용화는 호출 오버헤드/파라미터 전달 비용이 절감분보다 크거나, 컴파일러가 이미 인라인 처리. **4개 항목 전부 원복.**

### 2-4. 기타
- USART 서비스 명령에 `'R'`/`'r'`(테스트 카운트 리셋) 추가, RawDump에 버전/LOT 21바이트 헤더 추가(총 페이로드 248→269바이트).
- `Parameter_define.h` 정리(손상된 한글 주석 영문화, 미사용 define 삭제) 및 `CodeingCompleteReport.md`를 실제 코드 기준으로 최신화(스틱 감지 방식 서술 정정, 유효성 검증 단계 추가).
